## 0. 한눈에 보기

**문제.** 파인블랭킹 프레스 유압펌프의 이상을 진동(상부·하부)과 전류 시계열로 **일찍** 탐지하되, 정상 운전 변화를 이상으로 보는 **오경보를 줄이고** 미탐·오경보가 생기는 조건을 분석한다.

**데이터.** 정상 20,000행(2022-07-12, 77분), 이상 600행(2022-07-17, 2분 46초, **이상 이벤트 1건**), 센서 3개(AI0 상부 진동, AI1 하부 진동, AI2 전류), 10 Hz, 최대 5초 burst로 수집(세그먼트 정상 599 / 이상 21).

**접근.** 이상 라벨이 1건뿐이라 지도학습을 쓰지 않고, **정상 데이터만으로 학습**해 정상에서 벗어난 정도를 점수로 쓴다. 임계값은 학습용 정상 점수의 상위 1%(q99)로만 정하고 이상 데이터로 고르지 않는다.

**핵심 결과 6가지.**

| # | 결과 | 근거 |
|---|---|---|
| 1 | 원 데이터에는 **파일 형식 누수**가 있다(DC 오프셋 단독 AUC 0.89~0.94). 표준 전처리 후 형식 피처 AUC가 진동 0.566 / 전류 0.597로 내려간다 | §1.2 |
| 2 | 규칙 기반 베이스라인(1초 AUC 0.78~0.87)보다 딥러닝·통계 모델 다수가 AUC 0.999 이상. 실제 이상은 어느 모델이든 잡혀서 **오경보와 약한 이상 탐지력**이 모델을 가른다 | §2.2 |
| 3 | 서로 다른 계열(시계열 예측 + 통계)이 **서로 다른 곳에서 오경보를 낸다**(겹침 0.00~0.08). 둘의 동시 초과만 경보로 쓰면 세그먼트 오경보 2.8% → 0.2%, 실제 이상 미탐 0건 | §2.4 |
| 4 | 오경보는 **고부하 운전 구간**에 몰린다(예측 계열 고부하 2.7~3.0% vs 저부하 0%). 상태별 임계로는 해결되지 않고 결합이 해결한다 | §3.2 |
| 5 | 약한 초기 이상(합성 강도 1 이하)은 어떤 모델·결합도 잡지 못한다. 이건 이 데이터로 조기탐지를 주장할 수 있는 **한계선**이다 | §2.5 |
| 6 | 합성 열화에서 열화 완성 **전에** 주의가 울린다(선행 시간 중앙값 1.4 / 3.6 / 7.4분, 열화 2 / 5 / 10분). 단 이건 방법의 작동 확인이지 실제 고장 예측 성능이 아니다 | §4.3 |

**한계를 먼저.** 이상 이벤트가 1건이라 모든 정상 vs 이상 결과는 모집단 추론이 아니라 **이 이벤트의 기술**이다. 정상은 하루(77분)뿐이다. 이상과 정상은 날짜가 달라 정상 → 이상 전이 구간이 없으므로 "이상 N분 전 경보"는 실데이터로 검증할 수 없다.

## 1. 데이터 이해 및 진단 (심사 1번, 15점)

### 1.1 구성과 수집 방식

| 항목 | 정상 | 이상 |
|---|---|---|
| 행 | 20,000 | 600 |
| 기간 | 2022-07-12, 77분 | 2022-07-17, 2분 46초 |
| burst 세그먼트 | 599 | 21 |
| 결측·중복 | 0 · 0 | 0 · 0 |

- 타임스탬프는 단조 증가하고 역행 0건, burst 내부 간격 중앙값 0.1초(실효 10.0000 Hz)다 (리포트 04).
- 데이터는 연속이 아니라 **최대 50샘플(5초) burst**이고, burst 시작 간격 중앙값 7.958초(IQR 7.30~8.06), 활성 시간 비율(duty cycle) 42.03%다. 주기적 폴링 수집으로 보이나 [추정], 공백 구간의 값은 측정되지 않았다 (리포트 02).
- **공백 보간은 하지 않는다.** 공백이 2~17초로 burst만큼 길거나 더 길고, 보간값은 측정값이 아니라 만든 값이며 다음 burst를 쓰면 미래 정보가 섞인다. 대신 burst 간 정보는 burst별 점수의 시간 흐름으로 쓴다(`docs/final_design_JIW.md` §2.1).
- 센서 부착 위치: 가이드북은 "유압펌프 상/하단 진동센서·전력선 전류센서, 외부 설치"라고 하지만 사진상 유압 유닛이 모터-펌프 일체형이라 **원인이 모터인지 펌프인지 데이터로 구분할 수 없다.** 그래서 이 보고서는 탐지 대상을 "유압펌프 모터-펌프 구동부 이상"으로 쓴다.

### 1.2 누수 가능성과 차단

**표준 전처리** = 진동 6자리·전류 1.19209 격자 형식 통일 + 세그먼트 평균 제거. 모든 모델은 이 전처리와 같은 평가 계약을 쓴다: 세그먼트 단위 GroupKFold(`group_kfold_seg` 5) + 정상 시간순 블록(`time_block` 4), 임계 = train 정상 q99.

### 1.3 신호 특성

- **전류 에일리어싱**: 60 Hz 구동 전류가 10 Hz로 샘플링되며 0.6 Hz 사인으로 접힌다(정상 R² 0.9965). 결함 주파수 분석은 불가능하고 RMS·피크·첨도·크레스트 팩터 같은 시간영역 진폭 피처와 사인 피팅 이탈만 신뢰할 수 있다 (리포트 01·02·03).
- **진동 스케일**: 게인 동일성은 판정 불가(잡음 바닥 비율 0.385 / 0.334, 잡음 바닥 ≈ 진폭)라 형상(z-score) 피처를 병행한다 (03 A-2).
- **운전 상태 2개**: k-means 실루엣 0.5991로 고부하 43.18%(전류 RMS 평균 156.3) / 저부하 56.82%(86.4). 60~68분 저부하 구간 세그먼트 59개가 전부 저부하다 (리포트 02 §1).
- **정상 안의 변동**: 정상 의심 세그먼트 26개(4.9%), 블록 4는 저부하 85.71%로 분포가 다르다(블록 0~3은 46.67~55.00%) (리포트 04).

### 1.4 라벨 신뢰도

| 등급 | 진동 기준 | 전류 기준 |
|---|---|---|
| 확실 이상 | 18 | 7 |
| 경계 | 0 | 13 |
| 정상 유사 | 3 (세그먼트 3·19·20) | 1 (세그먼트 12) |

- 세그먼트 19·20은 진동은 조용한데 전류 DC가 198.5·180.1로 치우쳐 있다. 그런데 이 DC는 전류 RMS² 의 91.7%·96.4%이고 평균 제거 후 AC RMS는 59.6·35.2로 정상 중앙값(100.5)보다 낮다. **표준 전처리 후에는 3·19·20 모두 조용하므로 미탐은 라벨 노이즈를 먼저 의심한다** (리포트 02·31).
- 이상 이벤트 안에 **점진적 악화 추세는 없다**(AC 6피처 모두 p > 0.05, 최소 p 0.0745). "점진적 열화 예지" 서술은 철회했다 (리포트 04 E4).

## 2. AI 예측모델 개발 (심사 2번, 40점)

### 2.1 설계

- 이상 1건이라 **정상만으로 학습**(비지도). 입력은 전처리된 3채널 신호 또는 윈도우 진폭 피처 18열, 윈도우 1·2초(0.5초 간격).
- 모델 계열(KDD'25 시계열 이상탐지 서베이 분류): **Forecasting**(CNN-DeepAnT, LSTM-AD), **Graph**(MTAD-GAT, GDN), **Distribution**(MCD, OC-SVM, HBOS, COPOD, DeepSVDD), **Reconstruction**(CNN+LSTM 오토인코더, PCA 오토인코더, 가이드북 LSTM-AE 재현).
- 평가: 분할 2종 × 시드 3개, AUC·샘플/세그먼트 오경보율·탐지 지연·운전 상태별 오경보·합성 이상 탐지율. Point Adjustment는 쓰지 않는다.

### 2.5 결합 모델: 시계열 예측 + 통계 (리포트 28)

**아이디어.** 시계열 예측 모델(관점 A: 신호의 다음 값을 맞히고 틀린 정도)과 통계 모델(관점 B: MCD가 18개 피처 요약이 정상 무리에서 멀리 떨어진 정도)은 **서로 다른 곳에서 틀린다.** 각 모델의 점수를 자기 임계로 나눈 z로 바꾸고, **둘 다 1을 넘을 때만 경보**(AND, 임계는 결합 후 다시 구하지 않는다)로 쓴다.

| 규칙 (2초, group_kfold / time_block) | 세그먼트 오경보 | 시간당 오경보 | 실제 이상 | 합성 강도 2 |
|---|---|---|---|---|
| CNN 단독 | 2.8% / 1.8% | 10.0 / 6.3건 | 전부 탐지 | 0.744 / 0.714 |
| MCD 단독 | 3.8% / 3.1% | 13.3 / 10.8건 | 전부 탐지 | 0.251 / 0.325 |
| **CNN AND MCD** | **0.2% / 0.1%** | **0.8 / 0.3건** | 전부 탐지 | 0.235 / 0.315 |
| CNN OR MCD | 6.4% / 4.8% | 22.6 / 16.8건 | 전부 탐지 | 0.760 / 0.725 |

- **가설 검증(설계서 H1~H5)**: H1 통과(AND의 오경보 감소, 세그먼트 부트스트랩 95% 구간 −4.1 ~ −1.3%p / −3.1 ~ −0.6%p). H2 미달(강도 2에서 유지율 32% / 44%, 기준 70%). H3 관점 A는 CNN·LSTM-AD·MTAD-GAT 결합 결과가 같아 가장 가벼운 CNN 선택. **H4 기각**(상태별 임계로 고부하 오경보 3.2% → 3.1%). **H5 부분 기각**(k of n으로 오경보를 줄이면 실제 이상 창 탐지도 100% → 77%로 같이 떨어짐).
- **같은 계열끼리의 결합**(CNN AND LSTM)은 오경보가 2.8% → 2.1%로 줄어드는 폭이 작다. 서로 다른 계열을 합칠 때만 효과가 크다.
- **한계**: AND의 탐지율은 약한 쪽(MCD)에 묶여 약한 이상에서 크게 잃는다(강도 1: CNN 0.336 → AND 0.023). 실제 이상은 합성 강도 4~8 이상의 강한 이상이라 전부 잡혔다.

### 2.6 최종 모델: 포함 관계의 2단계 경보

| 단계 | 규칙 | 세그먼트 오경보 | 시간당 | 실제 이상 |
|---|---|---|---|---|
| 주의 | CNN 단독 초과 | 2.8% / 1.8% | 약 10 / 6건 | 전부 탐지 |
| 경보 | CNN AND MCD 초과 | 0.2% / 0.1% | 약 0.8 / 0.3건 | 전부 탐지 |

경보는 항상 주의의 부분집합이다. 주의는 점검 목록에 올리고 경보는 즉시 확인한다. 시간당 값은 세그먼트 오경보율 × 시간당 약 352.5 세그먼트(2초 윈도우가 있는 정상 세그먼트 452개 / 관측 76.93분)로 환산했다 [가정].

## 3. 영향요인 및 오류분석 (심사 3번, 15점)

### 3.1 미탐(FN): 두 종류로 나뉜다 (리포트 31 B)

| 유형 | 세그먼트 | 어떤 모델이 놓치나 | 해석 |
|---|---|---|---|
| (a) 단변량 규칙·진동 전용 입력의 한계 | 3·19·20 | 규칙 7종, 진동 2채널 오토인코더 | 표준 전처리 후 진동·전류 AC가 모두 조용함. **전류 채널을 입력에 넣은 모델은 모두 탐지**(미탐 0) |
| (b) 모델 특성 | 19 | COPOD·HBOS 계열, DeepSVDD (gkf 1초) | 피처 간 관계를 못 보는 모델 |

- 시사점: 조용한 이상의 탐지 여부는 **전류 AC 파형 정보**가 가른다. 현장 센서 구성에서 전류 채널은 선택이 아니라 필수다.
- 결합 규칙(28)에서는 4개 경보 규칙(단독·결합) 모두 **실제 이상 미탐이 0건**이다.

### 3.2 오경보(FP): 고부하 구간에 몰린다 (리포트 31 C, 28)

- 27개 모델 중 **19개가 고부하에 FP 집중**(BH 보정 p < 0.05). 예: CNN 고부하 7.52% vs 저부하 0.33%, MCD 9.29% vs 0.99%.
- 반복 FP 세그먼트(27모델 중 14개 이상): normal_460(22), normal_310(20), normal_52(17), normal_178(16), normal_569(15), normal_303·13(14). 과반 FP 7개는 전부 고부하이고 5개가 04 정상 의심 세그먼트와 겹친다.
- 윈도우 z-score 입력은 크기 정보를 지운 대신 저부하 오경보가 23%로 치솟는다. **크기를 지우면 오경보가 사라지는 게 아니라 위치가 바뀐다.**
- **상태별 임계 가설은 기각**했다(28 H4): 고부하 정상 점수는 고부하 안에서도 꼬리가 길어서 고부하 전용 q99를 써도 같은 비율로 넘는다(오경보 3.2% → 3.1%, 상태 추정 정확도는 고부하 89.3%). 고부하 오경보는 **MCD와의 AND**가 지운다.
- AND 후에 남은 오경보는 시드·분할 27개 중 4건이고 전부 **고부하 세그먼트의 창 1개짜리**다.
- 상관 구조: 정상 vs 이상에서 |Δρ| ≥ 0.5인 채널 쌍이 93/465이고 핵심은 **채널 관계 반전**(상·하부 진동 상관 정상 +0.28 → 이상 −0.35)이다. 정상 부분공간 이탈(PCA SPE·T²)은 이상 17세그먼트 전부 정상 q99를 넘는다 (리포트 31 D·E).

### 3.3 경보 근거 카드: 무엇 때문에 났나 (리포트 32)

경보가 날 때 어느 모델이 임계를 몇 배 넘었는지, CNN 예측 오차가 어느 센서에 몰렸는지, MCD 입력 중 정상에서 가장 벗어난 통계가 무엇인지를 코드로 뽑는다.

- 합성 이상에서 CNN 오차 비중 1위 채널이 주입한 채널과 **94~100% 일치**(강도 2 이상, 약한 경우는 상하 반대 흔들림 강도 1의 72%).
- 실제 이상 창 63개의 1순위 채널은 전류 48%, 상부 진동 43%, 하부 진동 10%이고 **세그먼트마다 다르다**(예: outlier_3 전류 95%, outlier_18 상부 진동 74%). 이상 이벤트 하나 안에서도 신호가 시간에 따라 바뀌므로 카드는 원인 부위를 단정하지 않고 "어느 신호가 벗어났는지"까지만 말한다.
- AND 오경보 카드는 CNN 배수 1.0·MCD 배수 1.7로 임계 바로 위였고, 실제 이상 창은 CNN 배수가 5.8~71.8이다.

## 4. 현장 활용방안 (심사 4번, 10점)

### 4.1 경보 운영 시나리오 [가정]

| 단계 | 규칙 | 거짓 사건(정상) | 조치 |
|---|---|---|---|
| 정상 | — | — | 모니터링 |
| 주의 | CNN 단독 초과 | 연속 경보를 한 사건으로 묶어 시간당 약 6건 | 점검 목록에 올리고 다음 정기 점검에서 확인, 근거 카드 첨부 |
| 경보 | CNN AND MCD 초과 | 시간당 약 0.3건 | 즉시 확인, 필요 시 정지 |

- 임계값은 **운영 시작 전 정상 데이터의 q99로 정하고** 이상 데이터로 조정하지 않는다. 정상 변동(블록 4처럼 저부하가 늘어난 구간, 04)이 있으므로 저부하가 오래 이어진 뒤에는 기준선을 갱신한다 [아이디어, 검증 전].
- 전환 직후 유예 창은 04에서 후보로 올린 아이디어이고, 상태 전환 효과는 교란이 있어 판정 보류 상태다 [추정].
- 판정 단위는 burst다. burst 간격 중앙값 7.958초가 **구조적 지연 하한**이다. 규칙 기반 탐지 지연 중앙값 0.9초 + burst 간격이 체감 지연(약 9.68초, 이 이벤트 1건의 관측값)이다.
- 세그먼트 단위 운영에는 윈도우 점수를 **평균한 뒤 판정**하는 집계가 유리하다(오경보 0.0264, 탐지 16.0/17). 2/3 연속 규칙으로 오경보를 0.0170으로 낮추면 탐지 1.7개를 잃는다 (리포트 27).
- **센서 구성**: 전류 채널은 필수(§3.1). 전류 사인 이탈이 조용한 이상을 가른다.

### 4.2 근거 카드와 챗봇 인터페이스 (리포트 32·34)

경보 알림에 근거 카드 문장을 붙이면 점검자가 확인 순서를 정할 수 있다. 같은 근거를 **대화로 묻고 답하는 챗봇**을 붙였다(`docs/chatbot_design_JIW.md`).

- **판정은 코드, 설명은 챗봇.** 경보 여부는 28번 규칙이 정하고 챗봇은 근거 카드와 결과 요약(facts 17개)을 풀어 설명한다. 챗봇이 틀려도 AUC·오경보율은 바뀌지 않는다. 원인(모터/펌프/부품)과 "N분 후" 시점은 단정하지 않고, 이런 질문은 규칙이 거절하며 이유를 댄다.
- **오픈소스 LLM을 로컬에서 실행**한다(허깅페이스 `Qwen/Qwen2.5-1.5B-Instruct`, Apache-2.0, 약 3GB, CPU). 외부로 아무것도 보내지 않아 규정·재현성 문제가 없다.
- **소형 모델에게 문장을 쓰게 하면 틀린다 [데이터 · 내 판독]**: 9개 중 6개가 틀렸고(주의 정의를 뒤집음, 다른 항목의 수치를 붙임 등), 숫자·단정 표현 검사는 0개를 잡았다. 그래서 **모델은 문장을 쓰지 않고 근거 번호만 고르게** 했다. 답은 근거 문장 그대로 나간다.
- **근거 고르기 성능 [데이터]**: 표현을 키워드에서 벗어나게 쓴 질문 17개(범위 안 14)에서 범위 안 적중이 키워드 규칙 14% → LLM 64%, 범위 밖 질문은 100% 거절. 프롬프트를 이 질문 세트로 두 번 고쳐서 낙관적이고, 범위 안 5개는 실패한다(틀려도 근거 문장 그대로라 거짓 문장은 없고 "근거에 없음"이나 엉뚱한 근거가 나온다).
- 소형 모델 1종만 시험했다. 더 큰 모델은 이 PC에서 느려 시험하지 않았다. 사용성은 평가하지 않았다.

점검 권고(상부 진동 → 상단 체결부·커플링·정렬, 하부 진동 → 하단 베이스·마운트, 전류 → 전원·부하 변동·토출 압력, 진동+전류 → 종합 점검)는 가이드북과 일반 설비 상식에서 온 **가정**이다. 현장 정비 기록으로 검증·수정해야 한다.

### 4.3 조기경보: 합성 열화 시나리오 (리포트 33)

실제 이상은 1건이고 정상 → 이상 전이가 없어 "N분 전 경보"를 실데이터로 검증할 수 없다. 그래서 test 정상 burst 열(약 15분)에 강도가 0 → 4로 서서히 커지는 합성 열화(4유형 × 2·5·10분 × 구간 4 × 시드 3 = 144 시나리오)를 넣었다. 강도 4는 실제 이상 수준(강도 4~8 이상)의 하한이다.

| 규칙 | 열화 2분 | 열화 5분 | 열화 10분 | 첫 경보 때 합성 강도 |
|---|---|---|---|---|
| 주의 (CNN 단독) | 1.39분 | 3.60분 | 7.39분 | 1.2 / 1.1 / 1.0 |
| 주의 (추세 EWMA λ0.4) | 1.50분 | 3.85분 | 8.27분 | 1.0 / 0.9 / 0.7 |
| 경보 (CNN AND MCD) | 0.98분 | 2.81분 | 6.71분 | 2.0 / 1.8 / 1.3 |

(열화 완성 전 선행 시간 중앙값. 전 시나리오에서 탐지, 주의는 전부 완성 전, 경보는 2·5분 열화의 88%만 완성 전.)

- 선행 시간은 열화 기간의 70~74%다. 첫 주의는 합성 강도가 약 1일 때 울린다. 그래서 "몇 분 전에 알린다"는 **실제 열화 속도에 달려 있고 이 데이터로는 알 수 없다.**
- 추세 규칙은 CNN 단독보다 평균 0.1 / 0.4 / 0.8분 일찍 울릴 뿐이다(같은 거짓 주의율 시간당 6.2건). 느린 열화에서만 의미 있어 선택 사항이다.
- **"약 N분 후 경보 도달" 문구는 쓰지 않는다.** 도달 시간 추정 오차(중앙값 1.5~2.4분)가 실제 남은 시간(0.7~1.5분)과 같거나 크다. 화면에는 "위험 상승 중"이라는 정성 표시만 한다.
- 정적 대시보드 `figures/33_early_warning_JIW/dashboard.html`: 시간 흐름, 선행 시간, 근거 카드 문장.

## 5. 창의성·차별성 (심사 5번, 10점)

1. **도메인 지식 기반 데이터 진단**: 에일리어싱(60 Hz → 0.6 Hz)과 파일 형식 누수를 규명하고 차단했다. 표준 전처리 후 형식 피처 AUC가 0.89~1.00 → 0.57~0.60으로 내려갔다.
2. **채널별 soft label과 라벨 노이즈 처리**: 진동 등급과 전류 등급을 따로 두고, 3·19·20 미탐을 모델 결함이 아니라 라벨 노이즈 후보로 분리했다.
3. **다중 관점 AND 결합**: 서로 다른 원리의 두 모델이 서로 다른 곳에서 틀린다는 점을 오경보 겹침으로 확인하고, 결합 임계를 다시 구하지 않는 "AND-고정"으로 오경보를 단독의 1/10 이하로 줄였다.
4. **강도별 합성 이상 평가**: 이상 1건 데이터에서 AUC가 천장에 닿는 문제를, 유형 4 × 강도 6단계의 합성 이상으로 모델의 약한 이상 탐지력을 가르는 방식으로 풀었다.
5. **합성 열화 시나리오 평가**: 정상 → 이상 전이가 없는 데이터에서 조기경보를 평가하는 방법을 설계하고, 결과를 "방법의 작동 확인"으로 한정했다.
6. **가설 기각의 기록**: 상태별 임계(H4), k of n(H5), 도달 시간 추정은 사전 가설을 세우고 검증해 **기각**했고 설계를 수정했다.
7. **근거 카드와 로컬 오픈소스 LLM 챗봇**: 경보 근거를 코드로 뽑아 문장으로 만들고, 소형 오픈소스 LLM이 질문에 맞는 근거 번호를 고르게 해 근거 문장 그대로 답한다. 소형 모델에게 문장 생성을 맡기면 틀린다는 것을 실험으로 확인하고 역할을 근거 검색으로 줄였다(표현을 바꾼 질문 적중 14% → 64%, 낙관적 추정).

## 6. 코드 및 재현성 (심사 6번, 10점)

- 실행 순서: `src/extract.py`(원본 해제) → 진단 노트북 01~04 → 전처리·피처 11~13 → 규칙 베이스라인 21 → 모델 24~27(+가이드북 재현) → 결합 28 → 분석 31 → 설명·조기경보 32·33(·34 챗봇).
- 경로는 `src/paths.py` 상수만 쓰고 노트북 결과는 `figures/<노트북>/`·`results/<노트북>/`에만 저장한다. 긴 로직은 `src/` 모듈(`preprocess`, `split`, `features`, `evaluate`, `stats`, `benchmark_*`, `ensemble_*`, `explain_*`, `early_warning_*`)에 둔다.
- 모델 노트북은 `results/<노트북>/metrics.csv`에 공통 컬럼(`model, split, fold, auc, fpr_sample, fpr_segment, delay_median_s`)을 저장하고, 비교표 `results/model_comparison.csv`는 분석 노트북 31이 합쳐 만든다.
- 시드: 시계열 모델 시드 0~2, 분할은 `group_kfold_seg` 고정, 부트스트랩 시드 고정.
- 가중치는 `models/`(git 제외)에 저장되고 있으면 불러온다. 점수 캐시(`data/processed/`)도 git 제외이며 없으면 노트북이 가중치로 다시 만든다. 가중치가 없으면 학습부터 다시 해야 한다.
- 노트북은 실행 결과를 포함해 커밋한다(에러 셀 0). 의존성은 `requirements.txt`에 고정한다.

## 7. 한계와 위험 (종합)

| 한계 | 영향 |
|---|---|
| 이상 이벤트 1건, 정상 하루(77분) | 정상 vs 이상 결과는 이 이벤트의 기술이다. 오경보율 신뢰구간이 넓다(0.1~0.2%는 세그먼트 한두 개 차이) |
| 이상과 정상이 다른 날 | 날짜 교란 가능성. 형식 누수는 차단했으나 설비 상태 차이와 측정 조건 차이를 구분할 수 없다 |
| 센서 부착 위치 미확정 | 원인이 모터인지 펌프인지 구분 불가, 점검 권고는 가정 |
| 정상 → 이상 전이·점진 악화 없음 | 조기경보는 합성 열화로만 평가. 실제 고장 예측 성능이 아님 |
| 합성 이상 4유형은 우리가 설계 | 이 유형에 유리할 수 있다 |
| 약한 초기 이상(강도 ≤ 1) 미탐 | 조기탐지 주장의 한계선 |
| MCD 임계가 fold마다 흔들림(2초 amp: group_kfold 616~1,427, time_block 360~595) | 결합 경보의 임계 안정성 |
| 점검 권고·시간당 오경보 환산은 가정 | 현장 검증 필요 |
| 챗봇은 소형 LLM 1종(1.5B)만 시험, 질문 세트·판독을 직접 만듦 | 근거 선택 적중 64%(낙관적), 범위 안 5/14 실패. 판정 성능에는 영향 없음 |
