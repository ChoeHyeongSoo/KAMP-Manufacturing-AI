## 0. 한눈에 보기

**문제.** 파인블랭킹 프레스 유압펌프의 이상을 진동(상부·하부)과 전류 시계열로 **일찍** 탐지하되, 정상 운전 변화를 이상으로 보는 **오경보를 줄이고** 미탐·오경보가 생기는 조건을 분석한다.

**데이터.** 정상 20,000행(2022-07-12, 77분), 이상 600행(2022-07-17, 2분 46초, **이상 이벤트 1건**), 센서 3개(AI0 상부 진동, AI1 하부 진동, AI2 전류), 10 Hz, 최대 5초 burst로 수집(세그먼트 정상 599 / 이상 21).

**접근.** 이상 라벨이 1건뿐이라 지도학습을 쓰지 않고, **정상 데이터만으로 학습**해 정상에서 벗어난 정도를 점수로 쓴다. 임계값은 학습용 정상 점수의 상위 1%(q99)로만 정하고 이상 데이터로 고르지 않는다.

**핵심 결과 7가지.**

| # | 결과 | 근거 |
|---|---|---|
| 1 | 원 데이터에는 **파일 형식 누수**가 있다(DC 오프셋 단독 AUC 0.89~0.94). 표준 전처리 후 형식 피처 AUC가 진동 0.566 / 전류 0.597로 내려간다 | §1.2 |
| 2 | 규칙 기반 베이스라인(1초 AUC 0.78~0.87)보다 딥러닝·통계 모델 다수가 AUC 0.999 이상. 실제 이상은 어느 모델이든 잡혀서 **오경보와 약한 이상 탐지력**이 모델을 가른다 | §2.2 |
| 3 | 최종 1초 체계에서 Ridge와 MCD의 정상 오경보가 거의 겹치지 않는다(Jaccard gkf 0.000 / time-block 0.041). 동시 초과만 경보로 쓰면 세그먼트 오경보가 2.06% → 0.00% / 1.70% → 0.25%로 줄고 실제 이상 17/17을 유지한다 | §2.5 |
| 4 | 최종 Ridge 오경보는 **고부하 운전 구간**에 몰린다(time-block 고부하 4.49% vs 저부하 0%). AND 경보는 이를 0.49%로 낮추며, 별도 상태별 임계는 모델 전반에서 일관된 이득이 없었다 | §3.2 |
| 5 | AND 경보는 약한 이상 민감도를 희생한다. 합성 강도 1 탐지율이 Ridge 0.3505에서 AND 0.1633으로 줄어, Ridge 단독을 **주의 단계로 반드시 유지**한다 | §2.5 |
| 6 | 별도 CNN+MCD 활용 프로토타입의 합성 열화에서는 열화 완성 전에 주의가 울렸지만, 이는 최종 Ridge 체계나 실제 고장 예측 성능이 아니라 **현장 활용 방법의 작동 확인**이다 | §4.4 |
| 7 | 최종 Ridge·MCD 점수, 운전 상태, 주의·경보를 서버 없이 열 수 있는 **정적 단일 HTML 대시보드**로 묶었다. 저장 데이터 replay이며 실제 설비 통신으로 표현하지 않는다 | §4.2 |

**한계를 먼저.** 이상 이벤트가 1건이라 모든 정상 vs 이상 결과는 모집단 추론이 아니라 **이 이벤트의 기술**이다. 정상은 하루(77분)뿐이다. 이상과 정상은 날짜가 달라 정상 → 이상 전이 구간이 없으므로 "이상 N분 전 경보"는 실데이터로 검증할 수 없다.

## 1. 데이터 이해 및 진단 (심사 1번, 15점)

### 1.1 구성과 수집 방식

| 항목 | 정상 | 이상 |
|---|---|---|
| 행 | 20,000 | 600 |
| 기간 | 2022-07-12, 77분 | 2022-07-17, 2분 46초 |
| burst 세그먼트 | 599 | 21 |
| 결측 · 중복 행 | 0 · 0 | 0 · 0 |

- 타임스탬프는 단조 증가하고 역행 0건, burst 내부 간격 중앙값 0.1초(실효 10.0000 Hz, 0.1초 ±5% 이탈 정상 1/19,401)다. 동일 시각 1건은 값까지 같은 중복이다 (리포트 04 B-1).
- 데이터는 연속이 아니라 **최대 50샘플(5초) burst**이고, burst 시작 간격 중앙값 7.958초(IQR 7.30~8.06, 최대 17.6초), 활성 시간 비율(duty cycle) 42.03%다. 주기적 폴링 수집으로 보이나 [추정], 공백 구간의 값은 측정되지 않았다 (리포트 02 §5).
- **공백 보간은 하지 않는다.** 공백이 중앙값 4.1초(5~95% 1.6~8.5초, 최대 16.5초)로 burst(중앙값 3.7초, 최대 5초)와 비슷하거나 더 길고, 보간값은 측정값이 아니라 만든 값이며 다음 burst를 쓰면 미래 정보가 섞인다. 마스킹·실제 공백 홀드아웃 검증에서 진동은 복원 불가(R² ≤ 0), 전류는 burst 안 2초까지만 복원되고 실제 공백에서는 R² −0.96으로 0 채움보다 나쁘다(burst 사이 위상 무작위, 리포트 14). 대신 burst 간 정보는 burst별 점수의 시간 흐름으로 쓴다.
- 세그먼트 길이는 고르지 않다. 정상 599개 중 50샘플(5초)은 202개, 10샘플(1초) 미만이 69개(중앙값 37샘플)이고 이상 21개 중 1초 미만이 4개다 (리포트 03). 그래서 **윈도우 길이에 따라 판정할 수 있는 세그먼트 수가 달라진다**(1초: 정상 530·이상 17, 2초: 정상 452·이상 13). 이 보고서는 1초 결과와 2초 결과를 같은 표에 섞지 않는다.
- 센서 부착 위치: 가이드북은 "유압펌프 상/하단 진동센서·전력선 전류센서, 외부 설치"라고 하지만 사진상 유압 유닛이 모터-펌프 일체형이라 **원인이 모터인지 펌프인지 데이터로 구분할 수 없다.** 그래서 이 보고서는 탐지 대상을 "유압펌프 모터-펌프 구동부 이상"으로 쓴다.

### 1.2 누수 가능성과 차단

| 진단 | 결과 | 출처 |
|---|---|---|
| 파일 형식 누수 | \|DC 오프셋\| 단독 AUC AI0 0.9443 / AI1 0.9198 / 전류 0.8911. 전류값 1.19209 배수 비율 정상 0.19% vs 이상 99.67%, 진동 소수 자릿수 형식 차이 | 리포트 02 §2 |
| 차단 확인 | 전처리 후 형식 피처 AUC 1.000 → 진동 0.566 / 전류 0.597 (통과 기준 ≤ 0.6) | 리포트 03 A-3 |

| 전류 파생 피처의 날짜 교란 | 전류 사인 잔차·전류 자기상관 피처는 단독으로 AUC 1.000 근방이고, 전류 1채널만 넣은 복원 모델도 AUC 1.000이다(27). 전류 채널이 이 이벤트의 날짜 차이를 담고 있을 가능성을 배제하지 못해 이런 피처군은 **별도 묶음**으로 보고한다 | 리포트 12·27·31 F |

**표준 전처리** = 진동 6자리·전류 1.19209 격자 형식 통일 + 세그먼트 평균 제거. 모든 모델은 이 전처리와 같은 평가 계약을 쓴다: 세그먼트 단위 GroupKFold(`group_kfold_seg` 5) + 정상 시간순 블록(`time_block` 4), 임계 = train 정상 q99, 세그먼트 판정 = 윈도우 하나라도 초과(any). 임계·표준화·PCA는 train fold 정상으로만 적합하고 이상 데이터로 임계·피처·하이퍼파라미터를 고르지 않는다.

### 1.3 신호 특성

- **전류 에일리어싱**: 60 Hz 구동 전류가 10 Hz로 샘플링되며 0.6 Hz 사인으로 접힌다(정상 R² 0.9965, 길이 50 정상 세그먼트 202개 전부 0.6 Hz가 최대 성분). 결함 주파수 분석은 불가능하고 RMS·피크·첨도·크레스트 팩터 같은 시간영역 진폭 피처와 사인 피팅 이탈만 신뢰할 수 있다 (리포트 01·02·03).
- **진동 스케일**: 게인 동일성은 판정 불가(잡음 바닥 비율 0.385 / 0.334, 잡음 바닥 ≈ 진폭)라 형상(z-score) 피처를 병행한다 (03 A-2).
- **운전 상태 2개**: k-means 실루엣 0.5991로 고부하 43.18%(전류 RMS 평균 156.3) / 저부하 56.82%(86.4). 60~68분 저부하 구간 세그먼트 59개가 전부 저부하다 (리포트 02 §1). 상태 전환은 599세그먼트 안에서 325회로 잦다 (04 E3).
- **정상 안의 변동**: 정상 의심 세그먼트 26개(4.3%)는 25개가 고부하라 사실상 고부하 진동 분포의 상단 꼬리다. 블록 4(마지막 약 15분)는 저부하 85.71%로 분포가 다르다(블록 0~3은 46.67~55.00%, KS 유의 열 12/15). time_block 분할에서 블록 4의 성능 변화는 먼저 이 정상 분포 이동으로 해석한다 (리포트 04).

### 1.4 라벨 신뢰도

| 등급 | 진동 기준 | 전류 기준 |
|---|---|---|
| 확실 이상 | 18 | 7 |
| 경계 | 0 | 13 |
| 정상 유사 | 3 (세그먼트 3·19·20) | 1 (세그먼트 12) |

- 세그먼트 19·20은 진동은 조용한데 전류 DC가 198.5·180.1로 치우쳐 있다. 그런데 이 DC는 전류 RMS² 의 91.7%·96.4%이고 평균 제거 후 AC RMS는 59.6·35.2로 정상 중앙값(100.5)보다 낮다. 표준 전처리 후에는 3·19·20 모두 단변량 진폭으로는 조용하다 (리포트 02·21).
- **그래도 이 3개의 미탐은 라벨 노이즈가 아니라 단변량 규칙·진동 전용 입력의 한계로 해석한다.** 전류 채널을 입력에 넣은 모델(예측·그래프·분포·전류 포함 복원 계열)은 모두 3·19·20을 탐지하고, 진폭 18열의 다변량 거리(PCA SPE·T²)로는 세 세그먼트가 정상 q99의 3.1~4.3배 밖에 있다(3번 4.29 / 3.73, 19번 3.41 / 3.08, 20번 3.68 / 3.89). 규칙 7종과 진동 2채널만 쓴 복원 모델만 같은 3개를 놓친다 (리포트 31 B·E). 라벨 노이즈는 후보 가설로만 남긴다.
- 이상 이벤트 안에 **점진적 악화 추세는 없다**(AC 6피처 모두 p > 0.05, 최소 p 0.0745). "점진적 열화 예지" 서술은 철회했다 (리포트 04 E4).

## 2. AI 예측모델 개발 (심사 2번, 40점)

### 2.1 설계

- 이상 1건이라 **정상만으로 학습**(비지도). 입력은 전처리된 3채널 신호 또는 윈도우 진폭 피처 18열, 윈도우 1·2초(0.5초 간격).
- 모델 계열(KDD'25 시계열 이상탐지 서베이 분류): **Forecasting**(CNN-DeepAnT, LSTM-AD), **Graph**(MTAD-GAT, GDN), **Distribution**(MCD, OC-SVM, HBOS, COPOD, DeepSVDD), **Reconstruction**(CNN+LSTM 오토인코더, PCA 오토인코더, 가이드북 LSTM-AE 재현).
- 평가: 분할 2종 × 시드 3개, AUC·샘플/세그먼트 오경보율·세그먼트 F1·탐지 지연·운전 상태별 오경보·합성 이상 탐지율. Point Adjustment는 쓰지 않는다.
- 비교용 임계는 train 정상 q99로 통일하지만, 같은 q99라도 실측 세그먼트 오경보율은 점수마다 다르다(1초 gkf: 규칙 1 0.0396 vs PCA SPE 0.0585, 리포트 31 A-3). 그래서 **운영 임계는 분위수가 아니라 목표 오경보율로 정한다**(§4.1).

#### 2.2.4 집계 규칙과 임계의 민감도 (리포트 31 A-3·A-4)

- 세그먼트 판정을 "윈도우 하나라도 초과(any)"에서 "n개 중 k개 초과(k-of-n)"나 "시작 윈도우 제외"로 바꾸면 같은 q에서는 F1이 오르는 것처럼 보이지만, 그 이득은 대부분 **오경보율이 함께 낮아진 효과**다. train 정상의 세그먼트 오경보율을 0.02·0.04로 맞춘 뒤 비교하면 8개 비교(2모델 × 2분할 × 2목표) 모두 any의 F1이 가장 높고(예: PCA SPE gkf 0.02: any 0.7234 vs k-of-n 0.7143 vs 시작 제외 0.6667), k-of-n은 recall(1.0000 → 0.8824)과 윈도우 내 지연(0.9 → 1.4초)을 잃는다. 28이 가설 H5(k of n)를 기각한 것과 같은 결론을 다른 방법으로 확인했다. 2모델·이상 1이벤트의 결과다 [추정].
- q를 0.99 → 0.999로 올리면 any는 fp만 줄어 F1이 단조 상승한다(규칙 1 gkf 0.5385 → 0.7778, PCA SPE 0.5231 → 0.9189). 대표 조건 q 0.99는 any에 가장 불리한 지점이라 표의 F1 절대값이 낮게 나온다. F1이 최대인 조합은 고르지 않았다(이상 1이벤트 과적합).

#### 2.2.5 최종 경보 구조의 두 구현 — 공통 세그먼트 비교 (리포트 31 A-5)

같은 2단계 구조(주의 = 예측 모델 단독 초과, 경보 = 예측 모델 AND MCD)를 28(CNN + MCD, 2초, 세그먼트 평균 제거 입력)과 23(Ridge-VAR + MCD, 1초, 1차 차분 입력)이 각각 구현했다. 분모가 달라 리포트별 수치를 나란히 둘 수 없으므로, 두 체계가 모두 판정하는 세그먼트(정상 452 · 이상 13)에서 저장된 윈도우 점수만으로 다시 셌다(재학습 없음, 시간당 계수 352.5 공통).

| 체계 | split | 단계 | 세그먼트 오경보 | 시간당 거짓 경보 | 이상 탐지 | 지연 중앙값 |

- 시사점: 예측 모델·입력·윈도우가 모두 다른 두 구현이 같은 수준의 결과를 낸 것은 "서로 다른 계열의 AND가 오경보를 줄인다"는 결론이 특정 모델 쌍에만 의존하지 않는다는 근거다. 오경보율 차이만으로는 둘을 가를 수 없으므로 최종 체계는 **causal 입력, 판정 범위, 탐지 지연, 계산량, 가중치 파일 없이 재현 가능한가**까지 함께 보고 23의 Ridge+MCD를 선택했다. 28의 CNN+MCD는 약한 합성 이상과 활용 프로토타입을 검증한 비선형 비교 체계로 보존한다. 두 결과 모두 같은 정상 하루·같은 이상 이벤트 1건 위의 것이다.

|---|---|
| G1 가이드북 원본 방식 | AUC 0.957, 오경보 111건 / 미탐 45건 (가이드북 보고치 78건 / 26건, 프레임워크 차이·시드 1개) |
| G2 팀 평가 계약 적용 (전처리·세그먼트 분할·train 정상 q99, 에폭 100으로 축소) | 2초 AUC 0.922(group_kfold) / 0.821(time_block), 세그먼트 오경보 3.5% / 6.3% |

G1·G2 차이의 원인(에폭·전처리·점수 방식)은 분리하지 않았다. 팀 계약 아래에서는 예측 계열(CNN·MTAD-GAT)이 더 낫다(AUC 1.000, 13/13 탐지 vs 가이드북 방식 0.92 / 0.82, 2초 time_block 13개 중 9~12개 탐지). 상세: `reports/29_model_guidebook_lstm_ae_JIW.md`.

### 2.5 결합 모델: 시계열 예측 + 통계 (리포트 23·28)

**아이디어.** 시계열 예측 모델(관점 A: 신호의 다음 값을 맞히고 틀린 정도)과 통계 모델(관점 B: MCD가 18개 피처 요약이 정상 무리에서 멀리 떨어진 정도)은 **서로 다른 곳에서 틀린다.** 각 모델의 점수를 자기 학습 정상 q99로 나눈 z로 바꾸고, **둘 다 1을 넘을 때만 경보**로 쓴다. 결합 후 임계를 다시 구하지 않는다.

최종 23 체계는 두 모델 모두 미래 샘플을 쓰지 않는다. Ridge는 burst별 1차 차분 3채널의 다음 값을 예측하고, MCD는 같은 차분 신호의 1초 진폭 피처 18개에서 강건 Mahalanobis 거리를 계산한다.

| 규칙 (1초, group_kfold / time-block) | 세그먼트 오경보 | 시간당 환산 | 실제 이상 | 합성 강도 1 |
|---|---|---|---|---|
| Ridge `[first_difference]` | 2.06% / 1.70% | 약 8.5 / 7.0건 | 17/17 | 0.3505 |
| MCD `[diff_amp]` | 4.29% / 8.63% | 약 17.7 / 35.7건 | 17/17 | 0.2180 |
| **Ridge AND MCD** | **0.00% / 0.25%** | **약 0.0 / 1.0건** | **17/17** | 0.1633 |
| Ridge OR MCD | 6.35% / 9.83% | 약 26.3 / 40.6건 | 17/17 | 0.4052 |

- 정상 FP Jaccard는 gkf 0.000, time-block 0.041이다. AND−Ridge 오경보율 차이의 세그먼트 쌍 부트스트랩 95% 구간도 각각 `−0.0340~−0.0094`, `−0.0264~−0.0048`로 0 아래다.
- AND는 실제 이상 17/17과 지연 중앙값 0.9초를 유지하지만 합성 강도 1 탐지율은 Ridge의 46.6%다. 따라서 AND 하나로 Ridge를 교체하지 않고 Ridge 초과를 주의, 두 모델 동시 초과를 경보로 쓴다.
- OR와 보정 평균은 실제 이상을 더 찾지 못하면서 오경보만 늘어 기각했다.

아래 2초 CNN+MCD 결과는 결합 가설과 약한 합성 이상을 별도로 확인한 비교 실험이다. 최종 운영 수치로 사용하지 않는다.

| 규칙 (2초, group_kfold / time_block) | 세그먼트 오경보 | 시간당 오경보 | 실제 이상 | 합성 강도 2 |
|---|---|---|---|---|
| CNN 단독 | 2.8% / 1.8% | 10.0 / 6.3건 | 전부 탐지 | 0.744 / 0.714 |
| MCD 단독 | 3.8% / 3.1% | 13.3 / 10.8건 | 전부 탐지 | 0.251 / 0.325 |
| **CNN AND MCD** | **0.2% / 0.1%** | **0.8 / 0.3건** | 전부 탐지 | 0.235 / 0.315 |
| CNN OR MCD | 6.4% / 4.8% | 22.6 / 16.8건 | 전부 탐지 | 0.760 / 0.725 |

- **가설 검증(설계서 H1~H5)**: H1 통과(AND의 오경보 감소, 세그먼트 부트스트랩 95% 구간 −4.1 ~ −1.3%p / −3.1 ~ −0.6%p). H2 미달(강도 2에서 유지율 32% / 44%, 기준 70%). H3 관점 A는 CNN·LSTM-AD·MTAD-GAT 결합 결과가 같아 가장 가벼운 CNN 선택. **H4 기각**(상태별 임계로 고부하 오경보 3.2% → 3.1%). **H5 부분 기각**(k of n으로 오경보를 줄이면 실제 이상 창 탐지도 100% → 77%로 같이 떨어짐).
- **같은 계열끼리의 결합**(CNN AND LSTM)은 오경보가 2.8% → 2.1%로 줄어드는 폭이 작다. 서로 다른 계열을 합칠 때만 효과가 크다.
- **한계**: AND의 탐지율은 약한 쪽(MCD)에 묶여 약한 이상에서 크게 잃는다(강도 1: CNN 0.336 → AND 0.023). 실제 이상은 합성 강도 4~8 이상의 강한 이상이라 전부 잡혔다.

### 2.6 최종 모델: Ridge-VAR + MCD의 포함 관계 2단계 경보

| 단계 | 규칙 | 세그먼트 오경보 | 시간당 | 실제 이상 |
|---|---|---|---|---|
| 주의 | Ridge `[first_difference]` 초과 | 2.06% / 1.70% | 약 8.5 / 7.0건 | 17/17 |
| 경보 | Ridge AND MCD `[diff_amp]` 초과 | 0.00% / 0.25% | 약 0.0 / 1.0건 | 17/17 |

경보는 항상 주의의 부분집합이다. 주의는 점검 목록에 올리고 경보는 즉시 확인한다. 수치는 `group_kfold / time-block` 순서이고 시간당 값은 세그먼트 오경보율 × 시간당 약 413.35세그먼트(1초 윈도우가 있는 정상 세그먼트 530개 / 관측 76.93분)로 환산했다 [가정]. 첫 Ridge 점수는 burst 시작 0.5초, 공통 1초 판정은 0.9초에 가능하다. 샘플별 Ridge 입력 변환·예측의 최악 처리시간은 0.388 ms로 10 Hz 주기 100 ms보다 충분히 작다(파일 I/O 제외).

공통 세그먼트에서 CNN+MCD와 오경보 차이는 통계적으로 구분되지 않았다. 최종 선택은 Ridge가 모든 합성 유형에서 우월해서가 아니라, 1초 causal 입력으로 이상 4개를 추가 판정하고 지연을 1초 줄이며 별도 딥러닝 가중치 없이 재현된다는 운영상 이점에 근거한다. CNN은 비선형 비교군으로 남긴다.

## 3. 영향요인 및 오류분석 (심사 3번, 15점)

### 3.1 미탐(FN): 두 종류로 나뉜다 (리포트 31 B·E)

1초 기준 판정 가능한 이상 세그먼트는 17개다(길이 1초 미만 0·5·9·10은 분모 밖). 미탐 세그먼트는 "전 채널 조용(3·19·20)"과 "기타"로 나눠 셌다.

| 유형 | 세그먼트 | 어떤 모델이 놓치나 (gkf 1초) | 해석 |
|---|---|---|---|
| (a) 단변량 규칙·진동 전용 입력의 한계 | 3·19·20 | 규칙 7종(causal 변형 3e 포함), 진동 2채널 오토인코더. 고전 Naive·Kalman은 19·20 | 표준 전처리 후 진동·전류 AC 진폭이 모두 조용함. 그러나 **전류 채널을 입력에 넣은 모델은 모두 탐지**(미탐 0)하고, 진폭 18열 PCA SPE·T²는 정상 q99의 3.1~4.3배 |
| (b) 모델 특성 | 19 | COPOD·HBOS 계열, DeepSVDD, Isolation Forest (각 1 fold) | 피처 간 관계를 보지 않는 단변량·독립 가정 분포 모델 |
| (c) 예외 | 3·4·14·18·19·20 | 가이드북 LSTM-AE(29, 팀 계약 적용) | 조용한 세그먼트뿐 아니라 기타 세그먼트도 놓침. 누수 제거와 학습 길이 축소의 효과는 분리하지 못함 |

- 주력 모델(CNN·LSTM-AD·MTAD-GAT·GDN·MCD·OC-SVM·Ridge-VAR)과 전류 포함 복원 모델은 gkf·time_block 모두 **미탐 0**이다. 1초 gkf 44행 중 25행이 미탐 0이라 모델 간 차이는 FN이 아니라 FP에서 난다(§2.2).
- 시사점: 조용한 이상의 탐지 여부는 **전류 AC 파형 정보**가 가른다(19·20은 평균 제거 후 전류 AC RMS가 정상 중앙값보다 낮은데도 파형 예측·복원 오차로 구분된다). 현장 센서 구성에서 전류 채널은 선택이 아니라 필수다. 규칙을 쓰려면 RMS 하나가 아니라 다변량 거리(T²·SPE)로 바꾸는 경량 대안이 있다.
- 결합 규칙(28·23)에서는 주의·경보 모두 **실제 이상 미탐이 0건**이다(§2.2.5).

### 3.2 오경보(FP): 고부하 구간의 진동 상단 꼬리에 몰린다 (리포트 31 C, 32 B, 28)

- gkf 1초 FP(32모델, 974행)를 정상 530세그먼트 분모(고부하 42.64% / 저부하 57.36%)로 환산하면 **32모델 중 23개가 고부하에 FP 집중**(Fisher, BH p < 0.05)이다. 예: CNN 고부하 7.52% vs 저부하 0.33%(OR 24.6), MCD 9.29% vs 0.99%, HBOS 12.39% vs 0.33%, Ridge-VAR 5.75% vs 0.66%. 8개는 차이 없음(OC-SVM 4종, 형상 변형 2종, 진동 2채널 AE, 가이드북 LSTM-AE)이고 1개(윈도우 z-score 입력 AE)만 저부하 집중이다.
- **고부하 집중을 모든 점수로 일반화하지는 않는다.** 오경보가 몰리는 상태는 점수마다 다르다: 목표 오경보율 0.02에서 규칙 1은 고부하 0.0488 vs 저부하 0.0062, PCA SPE는 고부하 0.0146 vs 저부하 0.0308이다(32 B). 윈도우 z-score 입력은 크기 정보를 지운 대신 저부하 오경보가 23%로 치솟는다. **크기를 지우면 오경보가 사라지는 게 아니라 위치가 바뀐다.**
- 반복 FP 세그먼트(32모델 중): normal_460(26), normal_310(22), normal_178·52(20), normal_569(18), normal_303(17), normal_422(16). 과반(16개 이상) FP 7개는 전부 고부하이고 6개가 04 정상 의심 세그먼트(26개)와 겹친다. 규칙 1의 FP 21개는 전부 고부하이고 19개가 04 의심과 겹친다. 04 의심 세그먼트가 모델별 FP에서 차지하는 비율은 예측·그래프 계열이 높다(CNN 44.4%, GDN 50.0%, LSTM-AD 47.6%, MTAD-GAT 68.8%; MCD·OC-SVM 6.8~27%).
- 시간 블록: 대부분 모델은 블록 4(저부하 85.7%)에서 FP율이 가장 낮다(CNN·MTAD-GAT 0.93%). MCD는 블록 2·3에 몰리고(10.1%·8.3%) OC-SVM은 블록과 무관하게 7~12%다.
- **상태별 임계 가설은 기각**했다. 28 H4(상태별 q99)는 고부하 오경보 3.2% → 3.1%였고, 32 B(상태별 목표 오경보율)는 12개 비교 중 고부하 오경보율 하락 4(모두 규칙 1)·동일 3·상승 5로 일관된 이득이 없었다(상태 추정은 전류 RMS 단일 경계, parquet 상태와 일치율 0.9442). 최종 23에서도 time-block 고부하 세그먼트 오경보가 Ridge 4.49%에서 AND 0.49%로 줄고 저부하는 둘 다 0%였다. 고부하 오경보를 줄이는 주 근거는 상태별 임계가 아니라 **다른 계열과의 AND**다.
- 상관 구조: 정상 vs 이상에서 |Δρ| ≥ 0.5인 채널 쌍이 93/465이고 핵심은 **채널 관계 반전**(예: 하부 진동 p2p–크레스트 −0.404 → +0.520, 상·하부 진동 상관이 포함된 쌍 0.68 → −0.37~−0.46)이다. causal 누적 상관에서도 같은 크기의 반전이 재현된다. 정상 부분공간 이탈(PCA SPE·T²)은 이상 17세그먼트 전부 정상 q99를 넘는다 (리포트 31 D·E).

### 3.3 경보 근거 카드 프로토타입: 무엇 때문에 났나 (리포트 32)

경보가 날 때 어느 모델이 임계를 몇 배 넘었는지, 예측 오차가 어느 센서에 몰렸는지, MCD 입력 중 정상에서 가장 벗어난 통계가 무엇인지를 코드로 뽑는 방법을 28의 CNN+MCD 점수로 구현했다. 아래 수치는 **설명 방법의 정합성 검증**이며 최종 Ridge+MCD 경보의 설명 결과로 해석하지 않는다. Ridge에도 채널별 표준화 예측오차와 MCD `[diff_amp]` 편차를 같은 카드 형식으로 붙일 수 있지만 이번 제출 실험에서는 재실행하지 않았다.

- 합성 이상에서 CNN 오차 비중 1위 채널이 주입한 채널과 **94~100% 일치**(강도 2 이상, 약한 경우는 상하 반대 흔들림 강도 1의 72%).
- 실제 이상 창 63개의 1순위 채널은 전류 48%, 상부 진동 43%, 하부 진동 10%이고 **세그먼트마다 다르다**(예: outlier_3 전류 95%, outlier_18 상부 진동 74%). 이상 이벤트 하나 안에서도 신호가 시간에 따라 바뀌므로 카드는 원인 부위를 단정하지 않고 "어느 신호가 벗어났는지"까지만 말한다.
- AND 오경보 카드는 CNN 배수 1.0·MCD 배수 1.7로 임계 바로 위였고, 실제 이상 창은 CNN 배수가 5.8~71.8이다.

## 4. 현장 활용방안 (심사 4번, 10점)

### 4.1 경보 운영 시나리오 [가정]

| 단계 | 규칙 | 정상 세그먼트 시간당 환산 | 조치 |
|---|---|---|---|
| 정상 | — | — | 모니터링 |
| 주의 | Ridge `[first_difference]` 초과 | 정상 세그먼트 기준 약 8.5 / 7.0건·시간 | 점검 목록에 올리고 다음 burst 추세 확인 |
| 경보 | Ridge AND MCD `[diff_amp]` 초과 | 정상 세그먼트 기준 약 0.0 / 1.0건·시간 | 즉시 설비 상태 확인, 필요 시 정지 판단 |

- 위 수치는 `group_kfold / time-block` 순서이며 23의 학습 정상 q99 규칙을 1초 판정 가능 세그먼트 413.35개/시간으로 환산한 값이다. 연속 경보를 묶은 사건 수가 아니다.
- 임계값은 **운영 시작 전 정상 데이터만으로 정하고** 이상 데이터로 조정하지 않는다. 이번 최종 판정은 23에서 검증한 q99(`z > 1`)를 쓴다. 정상 변동(블록 4처럼 저부하가 늘어난 구간, 04)이 있으므로 운전 상태 구성이 바뀌면 새 정상 구간으로 임계를 다시 검증한다 [아이디어, 검증 전].
- 전환 직후 유예 창은 04에서 후보로 올린 아이디어이고, 상태 전환 효과는 교란이 있어 판정 보류 상태다 [추정].
- 판정 단위는 burst다. 모델 내부 지연은 1초 체계 0.9초, 2초 체계 1.9초다. 정상의 시작→시작 간격 중앙값 7.958초를 더한 8.858초·9.86초는 수집 시나리오 참고치이며 실제 공백이나 일반적인 현장 지연 하한으로 단정하지 않는다. 이상 이벤트의 첫 판정 불가 burst에서 다음 burst까지 8.78초를 더한 9.68초는 이 이벤트 1건의 관측값이다(02 §8).
- 세그먼트 판정 집계는 **윈도우 하나라도 초과(any)** 로 통일한다. k-of-n 연속 규칙·시작 윈도우 제외는 오경보율을 맞춘 뒤 비교하면 F1 이득 없이 recall과 윈도우 내 지연(0.9 → 1.4초)을 잃는다(31 A-4, §2.2.4). 28의 H5(k of n) 기각과 같은 결론이다. 27 리포트의 "평균 후 판정·2/3 연속 규칙" 권고는 오경보율을 정렬하기 전의 관찰이라 채택하지 않는다.
- **센서 구성**: 전류 채널은 필수(§3.1). 전류 AC 파형 정보가 조용한 이상을 가른다.

**후속 운영점 절차 — 목표 오경보율로 임계를 합의하는 방법 (리포트 32)**

같은 q99라도 실측 세그먼트 오경보율은 점수마다 다르므로, 장기 운영에서는 "감당할 시간당 오경보 수"를 먼저 정하고 train 정상 점수에서 임계를 역산할 수 있다(`evaluate.threshold_for_segment_fpr`, 이상 데이터는 쓰지 않는다). 다만 32는 규칙 1과 PCA SPE에서만 이 절차를 검증했고 **최종 Ridge·MCD에는 적용하지 않았다.** 따라서 아래 결과는 운영점 선택 방법의 근거이며 최종 Ridge 임계 수치가 아니다.

| 항목 | 값 | 근거 |
|---|---|---|
| 시간당 환산 | 세그먼트 오경보율 × 413.35(1초 윈도우가 있는 정상 530개 / 76.93분). 2초 체계는 × 352.5(452개). 분모가 "윈도우가 있는 정상 세그먼트"라 윈도우 길이에 따라 다르다 | [데이터] 32 §1 |
| 운영점 예 (PCA SPE, gkf) | 목표 0.01: 실측 0.0113, 시간당 4.7회, recall 1.0000, F1 0.8500 / 목표 0.04: 0.0434, 17.9회, F1 0.5965 | [데이터] 32 A |
| 임계 입도 | train 정상 세그먼트 1개 = 0.24%p(gkf)·0.38%p(time_block), 가장 작은 train(113개)은 0.88%p → 목표는 0.01 이상, train 정상이 적을 때는 0.02 이상 | [데이터] 32 D |
| 2단계의 실측 이득 | 주의만 걸린 이상 세그먼트 0개. 주의가 경보보다 선행한 세그먼트 4/17(0.5~1.5초). 2단계의 가치는 탐지 추가가 아니라 **대응 등급 분리**이며 이 데이터로는 검증하지 못했다 | [데이터·추정] 32 C |
| 재학습 기준 | 월별 정상 오경보율이 목표의 2배 초과(목표 0.01에서 실측/목표 최대 1.68) 또는 운전 상태 분포 변화 → 정상 재수집 후 임계 재산정 | [가정] 32 §6 |

**p-value 보조 출력 (리포트 36).** 최종 Ridge·MCD 점수를 정상 calibration 세그먼트 대비 분할 컨포멀 p-value로 바꿔 "정상이라면 이만큼 극단적일 확률의 상한"이라는 같은 눈금을 붙일 수 있다. 이상일 확률이 아니며 `1 − p`를 이상 확률로 읽지 않는다. **이번 최종 판정은 23의 원 규칙(z > 1)을 유지하고 p-value는 보조 정보로만 쓴다.** 대표 정상 calibration을 충분히 확보하기 전에는 alpha를 주의·경보 판정에 사용하지 않는다.

- 해상도는 calibration 세그먼트 수가 정한다: alpha 0.01에는 99개 이상(약 14분 분량), 0.04에는 24개 이상이 필요하다. 설치·재보정 직후 그 시간 동안은 경보 alpha 0.01을 표현할 수 없다.
- 보장은 calibration 정상과 운영 정상의 **운전 상태 구성이 같을 때만** 성립한다. train의 가장 최근 25%(저부하가 많은 구간, 고부하 비율 0.17 vs test 0.43)로 calibration하면 gkf 실측 오경보율이 명목의 2.0~3.4배였고, 무작위 25%로 뽑으면 명목 근처로 돌아왔다(alpha 0.05: 0.1019 → 0.0453, 사후 분석). 이상 17세그먼트는 모든 분할에서 최소 p였다.
- 운영 규칙: calibration 구간은 최신이면서 고부하·저부하 구성이 현재 운전과 비슷해야 하고, 정상 구간에서 실측 오경보율이 alpha의 95% 구간 밖이면 이상이 아니라 calibration이 낡았다는 신호로 본다. 화면에는 `p = 0.009 (정상 calibration 106 burst 중 이보다 큰 점수 0개)`처럼 근거 개수와 함께 표시하고 강도는 원 점수(z)로 따로 보여 준다 [가정].

### 4.2 최종 Ridge·MCD 정적 대시보드 (리포트 37)

최종 운영 화면은 `figures/37_ridge_mcd_dashboard_JSC/dashboard.html`이다. 노트북 37이 23의 저장 점수와 `segments.csv`를 읽어 정상 운전·실제 이상 이벤트를 시간순으로 재생하고, **Ridge 주의 → 같은 창의 MCD 동시 확인 경보**를 표시한다. 그림·스타일·탭 전환 코드를 HTML 안에 넣어 브라우저로 직접 열 수 있으며 별도 서버·계정·DB·상용 라이선스가 필요 없다.

| 패널 | 표시 데이터 | 해석 |
|---|---|---|
| 운전 상태 | `state`(0 고부하 / 1 저부하) | 정상 time-block 평가 열의 상태 변화 |
| 주의 점수 | `z_ridge_diff`, 임계 1 | Ridge가 먼저 올리는 점검 후보 |
| 확인·경보 점수 | `z_mcd_diff_amp`, `z_ridge&mcd`, 임계 1 | 같은 창에서 두 관점이 모두 넘을 때만 경보 |
| 오류 사례 | `seg_uid`, 세그먼트별 최대 점수·초과 창 | 최종 정상 경보 `normal_178`, 서로 다른 창에서 넘은 `normal_331` 비교 |

- 성능 카드는 특정 화면 한 벌이 아니라 23의 전체 time-block fold·seed 평균을 사용한다: 주의 FPR 1.70%, 경보 FPR 0.25%, 판정 가능한 실제 이상 각각 17/17, 지연 중앙값 0.9초.
- 정상 화면은 fold 간 중복되지 않는 평가 블록 1~4의 417세그먼트(seed 0), 이상 화면은 같은 이벤트의 반복 표시를 피하려고 가장 많은 과거 정상으로 학습한 forward fold 4·seed 0 한 벌이다.
- **구현 범위:** 저장된 점수의 정적 스트림 재생까지다. 실제 센서/DAQ → causal 판정 서비스 → 점수·이벤트 저장 → 모니터링 패널·알림 흐름은 현장 배포 구조 `[가정]`이다. Grafana 등은 이 구조에서 사용할 수 있는 인터페이스 예시일 뿐 제출물에서 구축·검증하지 않았다.

### 4.3 근거 카드와 챗봇 인터페이스 — CNN+MCD 활용 프로토타입 (리포트 32·34)

경보 알림에 근거 카드 문장을 붙이면 점검자가 확인 순서를 정할 수 있다. 같은 근거를 **대화로 묻고 답하는 챗봇**을 붙였다(`docs/chatbot_design_JIW.md`). 이 인터페이스는 28의 CNN+MCD 결과로 구현한 활용 가능성 검증이며, 챗봇의 기존 CNN 수치를 최종 Ridge 성능으로 인용하지 않는다.

- **판정은 코드, 설명은 챗봇.** 경보 여부는 28번 규칙이 정하고 챗봇은 근거 카드와 결과 요약(facts 17개)을 풀어 설명한다. 챗봇이 틀려도 AUC·오경보율은 바뀌지 않는다. 원인(모터/펌프/부품)과 "N분 후" 시점은 단정하지 않고, 이런 질문은 규칙이 거절하며 이유를 댄다.
- **오픈소스 LLM을 로컬에서 실행**한다(허깅페이스 `Qwen/Qwen2.5-1.5B-Instruct`, Apache-2.0, 약 3GB, CPU). 외부로 아무것도 보내지 않아 규정·재현성 문제가 없다.
- **소형 모델에게 문장을 쓰게 하면 틀린다 [데이터 · 내 판독]**: 9개 중 6개가 틀렸고(주의 정의를 뒤집음, 다른 항목의 수치를 붙임 등), 숫자·단정 표현 검사는 0개를 잡았다. 그래서 **모델은 문장을 쓰지 않고 근거 번호만 고르게** 했다. 답은 근거 문장 그대로 나간다.
- **근거 고르기 성능 [데이터]**: 표현을 키워드에서 벗어나게 쓴 질문 17개(범위 안 14)에서 범위 안 적중이 키워드 규칙 14% → LLM 64%, 범위 밖 질문은 100% 거절. 프롬프트를 이 질문 세트로 두 번 고쳐서 낙관적이고, 범위 안 5개는 실패한다(틀려도 근거 문장 그대로라 거짓 문장은 없고 "근거에 없음"이나 엉뚱한 근거가 나온다).
- 소형 모델 1종만 시험했다. 더 큰 모델은 이 PC에서 느려 시험하지 않았다. 사용성은 평가하지 않았다.

점검 권고(상부 진동 → 상단 체결부·커플링·정렬, 하부 진동 → 하단 베이스·마운트, 전류 → 전원·부하 변동·토출 압력, 진동+전류 → 종합 점검)는 가이드북과 일반 설비 상식에서 온 **가정**이다. 현장 정비 기록으로 검증·수정해야 한다.

### 4.4 조기경보 프로토타입: CNN+MCD 합성 열화 시나리오 (리포트 33)

실제 이상은 1건이고 정상 → 이상 전이가 없어 "N분 전 경보"를 실데이터로 검증할 수 없다. 그래서 28의 CNN+MCD test 정상 burst 열(약 15분)에 강도가 0 → 4로 서서히 커지는 합성 열화(4유형 × 2·5·10분 × 구간 4 × 시드 3 = 144 시나리오)를 넣었다. 강도 4는 실제 이상 수준(강도 4~8 이상)의 하한이다. 이 수치는 활용 방법의 작동 확인이며 최종 Ridge+MCD의 선행 시간으로 이전하지 않는다.

| 규칙 | 열화 2분 | 열화 5분 | 열화 10분 | 첫 경보 때 합성 강도 |
|---|---|---|---|---|
| 주의 (CNN 단독) | 1.39분 | 3.60분 | 7.39분 | 1.2 / 1.1 / 1.0 |
| 주의 (추세 EWMA λ0.4) | 1.50분 | 3.85분 | 8.27분 | 1.0 / 0.9 / 0.7 |
| 경보 (CNN AND MCD) | 0.98분 | 2.81분 | 6.71분 | 2.0 / 1.8 / 1.3 |

(열화 완성 전 선행 시간 중앙값. 전 시나리오에서 탐지, 주의는 전부 완성 전, 경보는 2·5분 열화의 88%만 완성 전.)

- 선행 시간은 열화 기간의 70~74%다. 첫 주의는 합성 강도가 약 1일 때 울린다. 그래서 "몇 분 전에 알린다"는 **실제 열화 속도에 달려 있고 이 데이터로는 알 수 없다.**
- 추세 규칙은 CNN 단독보다 평균 0.1 / 0.4 / 0.8분 일찍 울릴 뿐이다(같은 거짓 주의율 시간당 6.2건). 느린 열화에서만 의미 있어 선택 사항이다.
- **"약 N분 후 경보 도달" 문구는 쓰지 않는다.** 도달 시간 추정 오차(중앙값 1.5~2.4분)가 실제 남은 시간(0.7~1.5분)과 같거나 크다. 화면에는 "위험 상승 중"이라는 정성 표시만 한다.
- 프로토타입 대시보드 `figures/33_early_warning_JIW/dashboard.html`: CNN+MCD 합성 열화의 시간 흐름, 선행 시간, 근거 카드 문장. 최종 Ridge·MCD 운영 화면은 §4.2의 37번을 사용한다.

## 5. 창의성·차별성 (심사 5번, 10점)

1. **도메인 지식 기반 데이터 진단**: 에일리어싱(60 Hz → 0.6 Hz)과 파일 형식 누수를 규명하고 차단했다. 표준 전처리 후 형식 피처 AUC가 0.89~1.00 → 0.57~0.60으로 내려갔다.
2. **채널별 soft label과 라벨 노이즈 처리**: 진동 등급과 전류 등급을 따로 두고, 3·19·20 미탐을 모델 결함이 아니라 라벨 노이즈 후보로 분리했다.
3. **다중 관점 AND 결합**: 서로 다른 원리의 두 모델이 서로 다른 곳에서 틀린다는 점을 오경보 겹침으로 확인하고, 결합 임계를 다시 구하지 않는 "AND-고정"으로 오경보를 단독의 1/10 이하로 줄였다.
4. **강도별 합성 이상 평가**: 이상 1건 데이터에서 AUC가 천장에 닿는 문제를, 유형 4 × 강도 6단계의 합성 이상으로 모델의 약한 이상 탐지력을 가르는 방식으로 풀었다.
5. **합성 열화 시나리오 평가**: 정상 → 이상 전이가 없는 데이터에서 CNN+MCD 활용 프로토타입으로 조기경보 평가 방법을 설계하고, 결과를 "방법의 작동 확인"으로 한정했다.
6. **가설 기각의 기록**: 상태별 임계(H4), k of n(H5), 도달 시간 추정은 사전 가설을 세우고 검증해 **기각**했고 설계를 수정했다.
7. **근거 카드와 로컬 오픈소스 LLM 챗봇**: 경보 근거를 코드로 뽑아 문장으로 만들고, 소형 오픈소스 LLM이 질문에 맞는 근거 번호를 고르게 해 근거 문장 그대로 답한다. 소형 모델에게 문장 생성을 맡기면 틀린다는 것을 실험으로 확인하고 역할을 근거 검색으로 줄였다(표현을 바꾼 질문 적중 14% → 64%, 낙관적 추정).
8. **데이터 조건을 설계 제약으로 명시**(§1.5): burst 간헐 수집을 판정 단위·지연 하한·운영 피처 조건으로 번역했다. 세그먼트 브로드캐스트 피처의 미래 정보를 causal 변형과의 차이로 정량화해(규칙 순위 이득의 약 1/3) 실시간 가능한 피처만 운영에 둔다.
9. **임계를 분위수가 아니라 목표 오경보율로 정의하는 운영점**(§4.1): 점수 종류와 무관하게 "시간당 오경보 몇 회"라는 같은 눈금으로 주의·경보 임계를 정하고, 집계 규칙(k-of-n)의 겉보기 이득이 오경보율 차이였음을 오경보율 정렬 비교로 분리했다. 여기에 분할 컨포멀 p-value를 보조 출력으로 붙여 보장이 성립하는 조건(calibration 크기·운전 상태 구성)과 깨지는 조건을 데이터로 보였다.
10. **비지도 선택과 평가 계약의 근거를 데이터 조건에서 도출**: 이상 1건·날짜 교란·운영 현실 때문에 정상만으로 학습하고, 임계·피처·하이퍼파라미터를 이상 데이터로 고르지 않으며, 두 윈도우 체계의 최종 구조를 공통 세그먼트에서 다시 세어 비교했다(§2.2.5).
11. **서버 없는 최종 운영 대시보드**: 최종 Ridge·MCD 점수와 2단계 대응 규칙을 단일 HTML로 묶어 외부 계정·DB·상용 도구 없이 재생성·열람하게 했다. 정상 replay와 이상 이벤트를 분리하고 구현 범위를 실제 센서 연결이 아닌 저장 데이터 재생으로 명시했다.

## 6. 코드 및 재현성 (심사 6번, 10점)

### 6.1 구조와 규칙

- 경로는 `src/paths.py` 상수만 쓰고(절대경로·`../` 하드코딩 없음) 노트북 결과는 `figures/<노트북>/`·`results/<노트북>/`에만 저장한다. 긴 로직은 `src/` 역할별 모듈에 둔다(`preprocess`, `split`, `features`, `evaluate`, `stats`, `conformal`, `benchmark_*`, `ensemble_*`, `realtime_*`, `explain_*`, `early_warning_*`, `dashboard_*`).
- 모델 노트북은 `results/<노트북>/metrics.csv`에 공통 컬럼(`model, split, fold, auc, fpr_sample, fpr_segment, delay_median_s`)을 저장하고, 비교표 `results/model_comparison.csv`(202행)는 분석 노트북 31이 모아 만든다. 직접 편집하지 않는다.
- 시드: 시계열 모델 시드 0~2, 분할은 `group_kfold_seg` 고정, 부트스트랩 시드 고정. 노트북은 실행 결과를 포함해 커밋한다(에러 셀 0). 의존성은 `requirements.txt`에 고정한다(Python 3.12, torch는 CPU 빌드).
- 가중치는 `models/`(git 제외), 점수 캐시는 `data/processed/`(git 제외)에 두고 있으면 불러온다. 없으면 노트북이 학습·재수집부터 다시 한다(`RETRAIN`·`RECOLLECT` 플래그).

### 6.2 재현 절차

```bash
python -m venv .venv && .venv/Scripts/activate      # macOS·Linux: source .venv/bin/activate
pip install -r requirements.txt
# data/ 에 원본 zip을 둔 뒤 (src/extract.py 는 노트북 첫 셀이 자동 호출)
python src/run_all.py                               # 노트북 25개 순차 실행, 로그 run_all_log.csv (CPU 약 2.5시간)
python src/run_all.py --only 24_model_forecasting_JIW,28_model_ensemble_JIW   # 일부만
python src/repro_compare.py                         # 재실행 결과를 커밋본과 대조(파일별 shape·최대 절대차·초과 셀 수)
```

실행 순서는 번호순이 아니라 **입력 계약**을 따른다: 01 → 02(세그먼트 표) → 03 → 11(윈도우 피처) → **04**(11의 parquet을 읽음) → 12 → 13 → 14 → 21 → 24 → 25 → 26 → 27 → 22 → 34(실시간 입력) → 23 → 29 → 28 → 31(비교표) → 32(운영점) → 32(근거 카드) → 33 → 35 → 36 → 37(최종 정적 대시보드). 34 챗봇은 로컬 LLM(약 3 GB) 다운로드가 필요해 순차 실행에서 제외한다(판정 성능과 무관).

### 6.3 재현성 점검 결과 (`docs/reproducibility_check.md`)

가중치와 점수 캐시를 모두 치운 상태에서 `src/run_all.py`로 24개 노트북을 처음부터 다시 돌리고 커밋된 결과 CSV와 비교했다(Windows, CPU, 합계 153분).

37번은 이 전체 점검 뒤 추가되어, 재생성된 23번 점수와 `segments.csv`를 입력으로 별도 실행했다. 계약 점검 6개(AND 점수 관계·정상 417개·이상 17개·이상 17/17 경보·저부하 경보 0개·저장 성능표 일치)가 모두 통과했고 외부 웹 자원 없이 단일 HTML을 생성했다. 따라서 기존 24개 전체 재실행과 37번 후속 실행을 구분해 기록한다.

## 7. 한계와 위험 (종합)

| 한계 | 영향 |
|---|---|
| 이상 이벤트 1건, 정상 하루(77분) | 정상 vs 이상 결과는 이 이벤트의 기술이다. 오경보율 신뢰구간이 넓다(0.1~0.2%는 세그먼트 한두 개 차이) |
| 이상과 정상이 다른 날 | 날짜 교란 가능성. 형식 누수는 차단했으나 설비 상태 차이와 측정 조건 차이를 구분할 수 없다 |
| 센서 부착 위치 미확정 | 원인이 모터인지 펌프인지 구분 불가, 점검 권고는 가정 |
| 정상 → 이상 전이·점진 악화 없음 | 조기경보는 합성 열화로만 평가. 실제 고장 예측 성능이 아님 |
| 합성 이상 4유형은 우리가 설계 | 이 유형에 유리할 수 있다 |
| 약한 초기 이상에서 AND 민감도 저하(강도 1: Ridge 0.3505 → AND 0.1633) | 확정 경보만으로 조기탐지를 주장할 수 없어 Ridge 주의 단계를 유지해야 함 |
| 최종 q99 임계는 정상 하루 안에서만 검증 | 다른 날짜·운전 구성에서 Ridge·MCD 임계 안정성을 다시 확인해야 함 |
| 점검 권고·시간당 오경보 환산은 가정 | 현장 검증 필요 |
| 챗봇은 소형 LLM 1종(1.5B)만 시험, 질문 세트·판독을 직접 만듦 | 근거 선택 적중 64%(낙관적), 범위 안 5/14 실패. 판정 성능에는 영향 없음 |
| 세그먼트 F1에 신뢰구간이 없음(이상 17개는 독립 표본이 아님) | 비교표의 F1 차이는 점추정이다. gkf(5 fold 합산)와 time_block(블록 평균)은 유병률·분모가 달라 서로 비교하지 않는다 |
| 1초·2초 체계는 판정 가능 세그먼트가 다름(정상 530·이상 17 vs 452·13) | 두 체계의 수치를 한 표에 두지 않고, 비교는 공통 세그먼트(§2.2.5)에서만 한다. 공통 이상은 13개뿐이고 모델·입력·윈도우가 동시에 달라 요소별 기여는 분리하지 못했다 |
| 시간당 오경보 환산은 정상 76.93분·판정 가능 세그먼트 기준 외삽 | 1초 413.35 / 2초 352.5 세그먼트·시간. 전체 599개 기준이면 13% 커진다. 다른 날짜·운전 구성에서는 다를 수 있다 |
| 운전 상태 추정은 전류 RMS 단일 경계(parquet 상태와 일치율 0.9442) | 상태별 오경보·상태별 임계 결과에 상태 추정 오차가 섞여 있다 |
| 목표 오경보율 운영점 분석은 2모델(규칙 1, PCA SPE)뿐 | 최종 Ridge·MCD에는 적용하지 않아 이번 판정은 23의 학습 정상 q99를 유지한다 |
| 컨포멀 p-value 보장은 calibration과 운영 정상의 운전 상태 구성이 같을 때만 성립 | 시간순 calibration에서 gkf 실측 오경보율이 명목의 2.0~3.4배. 무작위 calibration으로 회복됨을 사후 분석으로 확인했으나 사전 고정 설계가 아니다. alpha 0.01에는 calibration 99세그먼트 이상 필요 |
| torch 재학습은 시드 고정에도 환경에 따라 작은 수치 차이 | fpr_segment 0.003 이내, 29만 AUC 0.04. 결론·순위는 바뀌지 않았다(§6.3) |
