# 경보 설명 챗봇 설계서 (오픈소스 LLM 로컬 적용)

> **적용 범위 안내(2026-10-07).** 챗봇은 28번 CNN+MCD 결과와 32·33번 활용 프로토타입의 근거 문장을 사용한다. 최종 판정 모델은 Ridge+MCD로 변경됐으므로, 기존 CNN 수치는 최종 성능이 아니라 인터페이스 검증용 사실 집합으로만 사용한다.

> 목적: 경보 근거 카드(32번)와 결과 요약(28·33번)을 **대화로 묻고 답하는 인터페이스**를 제공한다. 심사 4번(현장 활용: 경보 → 조치 설명)과 5번(근거 기반 LLM 적용)에 기여한다.
> 구현: `src/chatbot_jiw.py`, 점검: `notebooks/34_alarm_chatbot_JIW.ipynb`, 리포트: `reports/34_alarm_chatbot_JIW.md`.
> 근거 표기: **[데이터]** 노트북 출력으로 확인 / **[가정]** 운영 전제 / **[미시험]** 실행해 보지 않음

## 1. 무엇을 하고, 무엇을 하지 않나

| 한다 | 하지 않는다 |
|---|---|
| 선택한 경보가 왜 났는지 근거 카드 문장으로 풀어 준다 | **경보를 판정하지 않는다.** 판정은 28번 규칙(코드)이 한다 |
| 오경보·미탐·조기경보·점검 권고·한계를 결과 수치로 설명한다 | 이상의 원인이 모터인지 펌프인지, 어떤 부품인지 **단정하지 않는다**(센서 부착 부위 미확정) |
| 근거에 없는 질문에는 "제공된 근거에 없습니다"로 답한다 | "N분 후 이상이 생긴다" 같은 **시점 예측을 하지 않는다**(도달 시간 추정 신뢰 불가, 33번) |

챗봇이 틀려도 탐지 성능(AUC·오경보율)은 바뀌지 않는다. 챗봇은 판정 뒤의 설명 계층이다.

## 2. 왜 오픈소스 모델을 로컬에서 돌리나

- **외부로 아무것도 나가지 않는다.** 대회 규정상 외부 API 허용 여부를 따질 필요가 없고, 데이터 반출 논의가 없다.
- **재현된다.** 모델 파일과 버전이 고정되고, 탐욕 디코딩이라 같은 입력에는 같은 출력이 나온다.
- 이 PC(RTX 4050 6GB, 환경의 torch는 CPU 빌드)에서 돌아가는 크기로 `Qwen/Qwen2.5-1.5B-Instruct`(Apache-2.0, 파라미터 1.54B, BF16 약 3GB)를 골랐다. CPU에서 질문당 약 5~25초다.
- 대가: 소형 모델의 한국어 성능이 제한적이다(§4). 더 큰 모델(예: 4B급)은 6GB GPU에 안 올라가 CPU로 느리게 돌려야 해서 **시험하지 않았다** [미시험].

## 3. 구조

```
질문 ─▶ 카드 질문? ──예──▶ 근거 카드 문장 + 해석 제한 문구 (템플릿)
        │아니오
        ▼
       원인 단정·시점 예측 질문? ──예──▶ 규칙이 거절하고 이유(F11·F15)를 댄다   ← 정책은 모델에 맡기지 않는다
        │아니오
        ▼
       키워드 규칙에 걸림? ──예──▶ 해당 근거 문장
        │아니오 (hybrid 모드)
        ▼
       도메인 단어 게이트 ──없음──▶ "제공된 근거에 없습니다."
        │있음
        ▼
       로컬 LLM이 근거 번호만 고름 ─▶ 그 근거 문장 그대로 출력

                         답 ─▶ 숫자 검증 · 단정 표현 검사 ─▶ 위반 시 근거 문장으로 대체
```

- **FACTS**: `results/28·32·33`의 CSV에서 읽은 수치 문장 17개(F1~F17). 결과를 다시 돌리면 값이 따라 바뀐다. 문장은 규칙 정의(F1·F2), 오경보·미탐 수치(F3~F7), 조기경보(F8~F11), 근거 카드(F12~F13), 점검 권고·부착 위치·한계(F14~F17)다.
- **CARD**: 32번 `cards.csv`에서 고른 경보 1건(`ChatSession.select_card`).
- **모델은 문장을 쓰지 않고 번호만 고른다**(select / hybrid 모드). 답이 근거 문장 그대로라 모델이 새 오류를 만들 수 없다. 틀릴 수 있는 것은 엉뚱한 근거를 고르거나 못 고르는 것뿐이고, 그건 눈에 보인다.
- `generate` 모드(모델이 문장을 새로 쓰는 방식)는 코드에 남아 있으나 **쓰지 않는다**. 이유는 §4.

## 4. 평가 결과 (`reports/34_alarm_chatbot_JIW.md`, 노트북 34)

| 점검 | 결과 | 한계 |
|---|---|---|
| 모델이 문장을 새로 쓰게 함(generate) | 9개 중 정확 1·부분 2·**오류 6**(내 판독). 숫자·단정 표현 검사는 **0건 감지** | 판독은 내가 했다. 오류 유형: 주의 정의 뒤집음, 다른 항목의 수치를 붙임, 근거와 반대 결론, 있는 근거를 "없다"고 거절 |
| 근거 번호 고르기(표현을 바꾼 질문 17개) | 범위 안 적중: 키워드 규칙 14% → LLM v1 43% → v2 64%, 범위 밖 거절 100%(도메인 단어 게이트) | 프롬프트를 이 세트로 두 번 고쳐 낙관적. 범위 안 5개는 못 고르거나 엉뚱한 근거 |
| 질문 세트 14개(오프라인/hybrid) | 14/14 | 14개가 모두 키워드 규칙에 걸려 LLM이 쓰이지 않음. 내가 쓴 질문 |
| 안전장치(대역이 규칙 위반 답을 냄) | 없는 숫자·원인 단정·시점 예측 3건 모두 감지되어 근거 문장으로 대체 | 정규식 휴리스틱. 위의 generate 오류 유형은 못 잡음 |

## 5. 운영 시 주의 [가정]

- 모델 파일(약 3GB)은 `models/`(git 제외)에 있다. 없는 환경에서는 `download_model()`로 한 번 내려받거나 오프라인 백엔드를 쓴다. 의존 패키지(`transformers` 등)는 `requirements.txt`에 버전을 고정했다.
- 모델이 근거를 못 고르면 "제공된 근거에 없습니다"로 답한다. 이 경우 질문을 다른 표현으로 다시 하거나 주제 목록을 보고 고른다. 현장 사용성은 평가하지 않았다 [미시험].
- 점검 권고 표(F14)는 가이드북과 일반 설비 상식에서 온 것이라 현장 정비 기록으로 검증·수정해야 한다.
- 대화 이력은 세션 안에서만 유지하고 파일에 저장하지 않는다.

## 6. 실행

```bash
python src/chatbot_jiw.py          # 오프라인 대화(키워드 규칙), '/card N'으로 경보 카드 선택
python src/chatbot_jiw.py --hf     # 로컬 LLM 포함(hybrid), 먼저 chatbot_jiw.download_model()로 모델을 받아 둔다
```
