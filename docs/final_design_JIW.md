## 1. 제안된 계획 요약

1. 시계열 모델 + 통계 정보를 함께 쓰는 멀티모달 또는 앙상블 모델
2. 세그먼트 사이 기록 공백을 보간해 연속 신호로 모델에 넣기 (정합성 검증 전제)
3. LLM으로 이상 원인과 위험 부위를 설명
4. 탐지뿐 아니라 "몇 분 후 이상 발생 위험" 예지
5. 출력: 이상 없음 / N분 후 이상 위험 / 이상 발생 시 위험 내용
6. 평가: 탐지와 예지를 분리, AUC·recall·precision·F1, 정상 사이에 이상을 넣어 탐지율, 예지는 정해진 시간 전에 경보가 울리는지
7. 간단한 대시보드

### 2.1 아이디어 2(보간)를 원 신호에 쓰지 않는 이유

**공백의 정체.** 가이드북은 "PLC 및 센서를 통해 실시간 데이터를 수신하여 수집된 시간을 기준으로 CSV로 저장"이라고만 쓰고 burst 수집 규칙은 밝히지 않는다. 데이터상 burst 시작 간격은 중앙값 7.958초(IQR 7.30~8.06), duty cycle 42.03%로 규칙적이다 [데이터: `reports/02_diagnosis_deep.md` §5]. 그래서 "프레스 행정 중에만 기록"보다는 **주기적 폴링 수집**에 가깝다 [추정]. 어느 쪽이든 공백 구간의 실제 값은 측정되지 않았다.

**보간이 안 되는 이유.**

| 문제 | 설명 |
|---|---|
| 정보 없음 | 공백이 burst 하나 길이와 비슷하거나 더 길다. 진동은 불규칙 신호라 양 끝값으로 중간을 복원할 수 없다 [데이터: §2.2 실험 완료 — `reports/14_gap_interpolation_check_JIW.md`] |
| 모델이 보간기를 학습 | 전체 시간의 약 58%(duty cycle 42%)가 보간값이 되면, 모델은 설비가 아니라 보간 방식(직선·스플라인)을 배운다 |
| 시간 누수 | 공백을 양쪽 burst로 채우면 **미래 burst**를 써서 현재를 판단하게 된다. 실시간 탐지와 맞지 않는다 |
| 이상 희석 | 이상 burst 사이를 매끄러운 값으로 채우면 이상 구간의 신호 특성이 왜곡된다 |

### 2.2 보간 정합성 검증 실험 (반나절)

"정합성 기준을 넘는지 체크"를 실험으로 수행해, 판정을 수치로 남긴다.

- 방법: 길이 50인 정상 burst에서 가운데 k샘플(k = 5, 10, 20, 30)을 가리고 선형 / 3차 스플라인 / (전류만) 사인 피팅으로 복원한다. 채널별 복원 R²와 RMSE를 정상 burst 내 표준편차와 비교한다.
- 합격 기준: R² ≥ 0.9이면 그 길이까지 보간 가능으로 본다.
- 예상: 전류는 0.6 Hz 사인(정상 R² 0.9965)이라 짧은 공백은 복원될 수 있고, 진동은 k = 5에서도 실패한다 [추정]. 실제 공백 길이에서는 모두 실패할 것으로 본다.
- 결과 활용: 보고서 1번(데이터 진단)에 "공백 보간 불가 근거"로 넣는다. 전류만 보간이 된다면 "전류 사인 위상 연속성"을 burst 간 피처 후보로 기록한다.

### 2.3 세그먼트 사이 정보는 이렇게 쓴다

공백을 채우는 대신 **burst 하나를 하나의 관측**으로 보고 burst 간 흐름을 본다.

```
burst t-n … burst t-1, burst t   →  각 burst의 이상 점수·피처 요약 + burst 간격 Δt
                                     → 지수가중 이동평균(EWMA)·기울기 → "위험 상승 추세" (§6)
```

측정하지 않은 값을 만들지 않고, 시간 간격 Δt를 그대로 쓴다.

### 2.4 아이디어 4(예지)를 줄이는 이유

| 필요한 데이터 | 우리 데이터 | 결과 |
|---|---|---|
| 정상 → 이상으로 넘어가는 전이 구간 | 없음. 정상은 2022-07-12, 이상은 2022-07-17로 날짜가 다르다 [데이터: 가이드북] | "이상 몇 분 전" 라벨을 만들 수 없음 |
| 여러 번의 고장 사례 | 이상 이벤트 1건 | 시간 예측 모델을 학습·검증할 수 없음 |
| 이상 구간 안의 점진적 악화 | 이상 21 burst 동안 AC 6피처 모두 추이 비유의(p > 0.05), 팀에서 "점진적 열화" 서술을 철회함 [데이터: `reports/04_data_profile_CHS.md` E4] | 이상 데이터 안에서도 악화 곡선이 없음 |

따라서 "N분 후 이상"을 실데이터 성능으로 주장하면 검증할 수 없는 주장이 된다. 대신 다음처럼 재정의한다.

- **조기탐지 = 약한(초기) 이상을 일찍 잡는 능력.** 실데이터 + 합성 강도별 탐지율로 평가한다.
- **예지 = 위험이 커지는 추세를 감지해 미리 "주의"를 내는 능력.** 정상 burst 열에 강도가 서서히 커지는 **합성 열화**를 넣어, 이상이 "확실한 수준"에 이르기 몇 분 전에 주의가 울리는지 측정한다(§6). 결과는 "합성 시나리오 기준"으로 명시한다.

### 2.5 아이디어 3(LLM)의 조건

| 위험 | 대응 |
|---|---|
| 원인 라벨이 없어 LLM이 말하는 "원인"을 검증할 수 없음 | "원인 진단"이 아니라 **관측 근거 + 점검 권고 위치 후보**로 범위를 한정 |
| LLM이 없는 사실을 만듦(환각) | 근거 추출을 코드로 먼저 하고, LLM에는 그 숫자만 주며 "주어진 사실만 사용" 지시. 출력 문장의 숫자가 입력 숫자와 같은지 자동 대조 |
| 센서 부착 부위 미확정 | "모터 이상" 또는 "펌프 이상" 단정 금지. "구동부 상부/하부 진동 이상"으로 표현 |
| 재현성(API 키, 비용, 매 실행 다른 문장) | 기본은 **템플릿 문장**(결정적). LLM 결과는 파일로 캐시하고, 키가 없으면 템플릿으로 대체 |
| 대회 데이터의 외부 전송 | 원 데이터는 보내지 않고 요약 수치만 전송. **대회 규정에서 외부 API 사용이 허용되는지 먼저 확인** [가정] |

### 2.6 평가 지표 보완

- **precision·F1의 한계**: 테스트 세트의 이상 비율(이벤트 1건, 21 burst)은 현장 비율이 아니라 데이터 구성의 결과다. 같은 모델도 정상 데이터를 더 넣으면 precision이 떨어진다. 그래서 precision·F1은 보고하되 주 지표로 쓰지 않는다.
- **주 지표**: 정상 q99 임계(오경보율 약 1%)에서의 recall, 세그먼트 오경보율, **시간당 오경보 건수**(2초 윈도우가 있는 정상 세그먼트 약 352.5개/시간 기준, 처음 쓴 452는 윈도우 없는 burst까지 센 값이라 정정), 탐지 지연.
- **Point Adjustment 미사용**: 구간 안 한 점만 맞혀도 구간 전체를 맞힌 것으로 치는 방식은 무작위 점수도 높게 만든다(Kim et al., AAAI 2022). 우리는 쓰지 않는다고 명시한다.

## 3. 탐지 모델: 다중 관점 결합

### 3.1 구조

```
                    ┌─ 관점 A: 원 신호 시퀀스 ─▶ 시계열 모델 예측 오차 ───┐
burst (전처리 후) ──┤                                                      ├─▶ 결합 규칙 ─▶ 정상/주의/경보
                    └─ 관점 B: 윈도우 통계 18열 ─▶ MCD 마할라노비스 거리 ──┘        │
                                                                              운전 상태별 임계
```

관점 A 모델은 고정하지 않고 H3에서 고른다. 단독 성능(2초, gkf / tb 세그먼트 오경보)은 MTAD-GAT 2.2% / 2.5%, LSTM-AD 2.6% / 1.7%, CNN 2.8% / 1.8%로 차이가 작고, 합성 약한 이상 탐지는 CNN 0.308, MTAD-GAT 0.306, LSTM-AD 0.289다 [데이터: `results/model_comparison.csv`, `docs/model_guide_JIW.md` §6]. 복원 계열(27번 CNN+LSTM AE 6.4% / 9.3%, 가이드북 LSTM-AE 3.5% / 6.3%)은 단독 오경보가 더 높다.

"멀티모달"보다 **다중 관점(multi-view)** 이 정확한 표현이다. 두 입력이 같은 센서 신호에서 나오기 때문이다(원 신호 vs 요약 통계).

### 3.2 결합 방식: 점수 단계 결합

| 방식 | 판단 | 이유 |
|---|---|---|
| **점수 단계 결합(late fusion)** | **주 방법** | 저장된 가중치 재사용, 각 모델 임계 유지, 해석 쉬움, 효과 이미 확인 |
| 입력 단계 결합(신호+피처를 한 신경망에) | 시간이 남으면 실험 | 정상 약 2,300 윈도우로 새 신경망을 학습하면 과적합 위험, 4일 안에 검증까지 어려움 |

### 3.3 규칙

| 단계 | 규칙 | 목적 |
|---|---|---|
| 주의 | CNN **OR** MCD 임계 초과 + 연속 규칙(최근 n개 중 k개) | 약한 이상을 넓게 |
| 경보 | CNN **AND** MCD 임계 초과 (각 모델의 q99를 그대로 둠) | 오경보 최소 |
| 상태별 임계 | 고부하/저부하 각각 q99, 상태는 전류 RMS 경계 125.2로 추정 | 고부하 오경보 감소 |

### 3.4 검증 가설 (기존 H1~H5 유지)

| # | 가설 | 성공 기준 |
|---|---|---|
| H1 | AND의 오경보 감소가 시드·fold에 상관없이 재현 | CNN 단독 대비 세그먼트 오경보 차이의 95% 부트스트랩 구간이 0 미만 |
| H2 | AND가 합성 강도 2에서 탐지율 유지 | CNN 단독 대비 70% 이상 |
| H3 | 관점 A(시계열) 모델 선정 | {CNN, LSTM-AD, MTAD-GAT} × MCD 결합을 비교해 오경보·합성 탐지가 가장 좋은 조합을 고른다. 27번(CNN+LSTM AE, 팀원)은 `scores.csv`가 같은 윈도우 단위면 후보에 추가 |
| H4 | 상태별 임계가 고부하 오경보 감소 | 고부하 FP 2.7% → 1.5% 이하 |
| H5 | 주의 단계 오경보를 연속 규칙으로 감소 | 오경보 감소폭 대비 지연 증가폭 보고 |

| 평가 | 데이터 | 지표 |
|---|---|---|
| E1 실제 이상 | 팀 계약 분할(gkf 5 + time_block 4) | AUC, recall@q99, 세그먼트 탐지율, fpr_sample·fpr_segment, 시간당 오경보, 탐지 지연 |
| E2 정상 흐름 안의 실제 이상 | 테스트 정상 burst 열 중간에 실제 이상 21 burst를 시간 순서대로 끼워 넣음 | 이벤트 탐지 여부, 첫 경보까지 burst 수·초, 이벤트 전후 오경보 |
| E3 합성 이상 | 정상 burst에 4유형(스파이크·진폭·반대 흔들림·전류 불규칙) × 강도 4단계 주입 | 유형·강도별 recall, AUC, precision·F1(참고) |

E2는 "정상 데이터 중간에 이상 데이터를 넣어 탐지 비율 보기"를 실제 이상으로 구현한 것이다. 이상은 다른 날 데이터이므로, 표준 전처리(`preprocess.preprocess()`)로 파일 형식 차이를 없앤 뒤 이어 붙인다.

## 5. 설명 모듈: 근거 카드

### 5.1 흐름

```
경보 발생 ─▶ ① 근거 추출 (코드, 결정적)
              - 어느 모델이 넘었나 (CNN / MCD / 둘 다), 임계 대비 배수
              - 센서별 기여: CNN 채널별 예측 오차, MCD 피처별 기여(표준화 편차)
              - 가장 벗어난 피처 상위 3개와 정상 분포 백분위
              - 운전 상태(고부하/저부하), 최근 n burst의 점수 추세
         ─▶ ② 근거 카드 JSON
         ─▶ ③ 문장 생성: 템플릿(기본) / LLM(선택, 캐시)
         ─▶ ④ 점검 권고: 근거 유형 → 점검 항목 매핑표
```

### 5.2 근거 유형 → 점검 권고 (원인 단정이 아닌 점검 후보)

| 관측 근거 | 표현 | 점검 권고 후보 [가정] |
|---|---|---|
| 상부 진동만 크게 이탈 | 구동부 상부 진동 이상 | 상단 체결부·커플링·정렬 점검 |
| 하부 진동만 크게 이탈 | 구동부 하부 진동 이상 | 하단 베이스·마운트 점검 |
| 상·하부 반대 방향 흔들림 | 상·하부 진동 관계 이상 | 축 정렬·편심 점검 |
| 전류 사인 파형 이탈 | 전류 파형 이상 | 전원·부하 변동, 토출 압력 점검 |
| 진동 + 전류 동시 | 구동부 전반 이상 | 즉시 정지 후 종합 점검 |

점검 권고는 가이드북과 일반 설비 상식에서 온 **가정**이며, 이 데이터로 검증한 것이 아니다. 보고서에 그렇게 쓴다.

### 5.3 평가

- 원인 라벨이 없으므로 "설명의 정확도"는 측정할 수 없다.
- 대신 **합성 이상으로 근거 추출의 정합성**을 평가한다. 상부 진동에 스파이크를 넣었으면 근거 카드가 "상부 진동"을 1순위로 꼽는지 본다(유형별 적중률).
- 미탐·오경보 사례마다 근거 카드를 모아 "어떤 조건에서 틀리는가"(심사 3번)를 집계한다.

## 6. 조기경보(예지) 모듈

### 6.1 출력

| 단계 | 조건 | 출력 문장 예 |
|---|---|---|
| 정상 | 주의 조건 미충족 | 이상 없음 |
| **주의(위험 상승)** | 최근 burst들의 결합 점수 EWMA가 상승 추세 + 주의 규칙 충족 | "상부 진동 이탈이 최근 5분간 증가 중. 현재 추세가 이어지면 약 N분 후 경보 수준 도달 [추정]" |
| 경보 | 경보 규칙 충족 | "구동부 상부 진동 이상. 점검 권고: …" |

"N분 후"는 점수 추세를 경보 임계까지 선형 외삽한 값이다. 실데이터로 검증할 수 없으므로 화면과 보고서에 **추정치**로 표시하고, 합성 시나리오에서의 오차를 함께 적는다.

### 6.2 합성 열화 시나리오로 평가 ("정해진 시간 전 경보" 평가)

```
강도
 2 ┤                              ●●●●  ← 위험 수준 도달 시점 T_crit
 1 ┤                      ●●●●●●
0.5┤              ●●●●●●●
 0 ┼●●●●●●●●●●●●●                    → 시간 (burst 열, 약 8초 간격)
    정상 구간     열화 시작 T0
```

- 테스트 정상 burst를 시간 순서대로 이어 붙이고, T0 이후 burst에 합성 이상을 강도 0 → 2로 서서히 키워 넣는다(유형 4종, 열화 기간 3종: 2·5·10분).
- T_crit = 강도가 "실제 이상 이벤트 수준"에 이르는 시점. 이 수준은 실제 이상 burst의 점수 분포로 정한다.
- 지표
  - **선행 시간** = T_crit − 첫 주의 시각 (분). 클수록 좋음
  - **조기경보 적중률** = 선행 시간 ≥ L분(L = 1, 3, 5)인 시나리오 비율
  - **정상 구간 거짓 주의율** = 열화 시작 전 구간의 시간당 주의 건수
  - **도달 시간 추정 오차** = |예측 N분 − 실제 남은 시간|
- 한계: 열화 곡선과 이상 유형을 우리가 정했으므로 실제 고장의 진행과 다를 수 있다. 결과는 "방법의 작동 확인"이지 "실제 고장 예측 성능"이 아니다.
