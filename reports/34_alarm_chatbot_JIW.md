## 1. 발견 [데이터 · 내 판독]

### 1.1 소형 모델에게 문장을 쓰게 하면 그럴듯하게 틀린다

질문과 관련된 근거만 주고 답을 자유롭게 쓰게 했을 때(generate 모드) 9개 중 6개가 틀렸다(내가 근거 문장과 대조해 읽음).

| 질문 | 모델 답의 문제 |
|---|---|
| 경보랑 주의는 뭐가 달라? | 주의를 "CNN과 MCD 중 하나라도 넘으면"으로 설명(실제 주의는 CNN 단독) |
| 약한 이상도 잡아? | 첫 문장이 "잡을 수 있습니다"로 근거(거의 못 잡음)와 반대 |
| 미탐은 어떤 경우야? | "합성 열화 또는 합성 이상일 때 발생"으로 틀리게 일반화 |
| 이 결과를 얼마나 믿을 수 있어? | 한계 근거가 있는데 "근거에 없습니다"로 과도하게 거절 |
| CNN 단독이랑 MCD 단독 비교해줘 | CNN 단독 항목에 경보(AND) 수치 0.2% / 0.1%를 붙임 |
| 고부하에서 오경보가 왜 많아? | 수치는 맞으나 원인 서술이 뒤섞임 |

**코드 검사(답의 숫자가 근거에 있는지, 원인·시점 단정 표현)는 9개 중 0개를 잡았다.** 틀린 답의 숫자도 근거 안에 실제로 있는 값이라 숫자 존재 여부로는 보이지 않는다. 설계 초안의 "숫자 검증이면 환각을 막는다"는 가정이 이 모델에서는 성립하지 않았다.

### 1.2 모델에게는 근거 번호만 고르게 한다

설계를 바꿔 모델이 **근거 번호만 고르고 답은 근거 문장 그대로** 출력하게 했다. 표현을 일부러 키워드에서 벗어나게 쓴 질문 17개(범위 안 14, 범위 밖 3)로 비교했다.

| 방식 | 범위 안 적중 | 범위 밖 거절 | 정밀도 |
|---|---|---|---|
| 키워드 규칙 | 0.143 | 1.000 | 0.211 |
| LLM v1 (번호 목록만) | 0.429 | 1.000 | 0.529 |
| LLM v2 (지시·예시 추가) | 0.643 | 0.333 | 0.559 |
| LLM v2 + 도메인 단어 게이트 | 0.643 | 1.000 | 0.676 |
| hybrid (규칙 → LLM) | 0.643 | 1.000 | 0.593 |

- 키워드 규칙은 표현이 바뀌면 14개 중 2개만 맞힌다. LLM은 9개를 맞힌다.
- v2는 범위 안 적중을 올렸지만 점심 메뉴 같은 범위 밖 질문에도 근거를 골랐다(거절 33%). 도메인 단어 게이트가 막았다.
- **범위 안 5개는 여전히 실패**한다(예: "알림이 울리는 상황"과 "통계 모델을 같이 쓰는 이유" 두 질문에 센서 위치 근거를 고름). 틀려도 근거 문장 그대로가 나오므로 거짓 문장은 생기지 않지만 질문에 맞지 않는 답이 나온다.
- hybrid는 규칙을 먼저 쓰므로 키워드가 질문을 잘못 보내는 경우가 있다("어디서 문제가 제일 **자주** 보였어?"가 오경보 근거로 감 — LLM만 쓰면 맞힌 질문). 적중은 같지만 정밀도는 LLM v2 + 게이트(0.676)가 hybrid(0.593)보다 높다. hybrid를 기본으로 둔 이유는 14개 핵심 질문의 규칙 경로(거절 정책 포함)를 모델 변동 없이 고정하려는 것이다.
- **한계**: v1 → v2와 게이트는 이 질문 세트를 보고 고쳤다. 적중률은 낙관적이다.

### 1.3 나머지

- 질문 14개 점검은 오프라인·hybrid 모두 14/14인데, 14개가 전부 키워드 규칙에 걸려 **LLM이 쓰이지 않았다.** hybrid 배선이 규칙 경로를 해치지 않는다는 확인이다.
- 원인 단정·시점 예측 질문은 모델에 맡기지 않고 규칙이 거절하고 이유(F11·F15)를 댄다. 거절은 정책이라 소형 모델에 둘 수 없다.
- 안전장치: 대역이 낸 규칙 위반 답(없는 숫자 99.9, 모터 베어링 고장 단정, 3분 후 도달 예측) 3건 모두 감지되어 근거 문장으로 대체됐다.
- 속도: 모델 로드 약 16초, 근거 선택 질문당 약 5초(CPU), 문장 생성은 약 20초.

## 2. 시사점

- 챗봇은 판정 뒤의 **설명 계층**이다. 챗봇이 틀려도 AUC·오경보율은 바뀌지 않는다.
- 소형 오픈소스 모델은 **문장 생성이 아니라 근거 검색(번호 고르기)**에 쓸 때 안전하고 도움이 된다. 표현이 다양한 질문을 키워드 규칙보다 4배 이상 잘 받아낸다(14% → 64%).
- 외부 호출이 없어 규정·재현성 문제가 없다. 모델이 못 고르면 "근거에 없음"으로 끝나는 안전한 실패다.

## 3. 현장 활용 [가정]

- 경보 알림에 카드 문장을 붙이고, 점검자가 "이 경보 왜 울렸어?", "어떻게 점검해?"를 묻는다. 표현이 달라도 약 2/3는 맞는 근거가 나오고, 나머지는 "근거에 없음"이나 엉뚱한 근거가 나오므로 주제 목록에서 고르게 안내한다.
- 점검 권고 표는 가정이라 현장 정비 기록으로 검증·수정해야 한다.

## 4. 한계

- 소형 모델(1.5B) 한 종류만 시험했다. 더 큰 모델(예: 4B급)은 이 PC의 6GB GPU에 안 올라가 CPU로 느리게 돌려야 해서 **시험하지 않았다.** 근거 선택 적중률이 어디까지 오를지는 모른다.
- 질문 세트(17개, 14개, 9개)는 내가 만들었고 판독도 내가 했다. 독립 평가가 아니다.
- 근거 선택 프롬프트·게이트를 같은 질문 세트로 고쳤다. 새 질문에서의 적중률은 이보다 낮을 수 있다.
- 사용성(현장 점검자가 실제로 도움을 받는지)은 평가하지 않았다.
- 판정 정확도와 챗봇은 분리돼 있어 챗봇 오류가 탐지 성능에 영향을 주지 않지만, 잘못된 근거가 선택되면 점검 순서를 오도할 수 있다.
