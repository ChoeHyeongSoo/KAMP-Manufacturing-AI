## 0. 결론 요약

현재 데이터는 연속 스트림이 아니라 **최대 5초 길이의 burst 세그먼트가 반복되는 구조**다. 정상과 이상 데이터 모두 같은 형태이고 세그먼트 내부의 10 Hz 간격은 안정적이므로, 세그먼트 경계는 설비 이상으로 신호가 끊긴 흔적이라기보다 **공정 사이클 또는 수집·저장 정책에 의해 생긴 구조일 가능성이 높다**. 다만 수집 사양서가 없어 의도된 미측정인지 일부 구간의 미저장인지는 아직 확정할 수 없다.

원인에 대한 최종 확인이 남아 있더라도 모델링 처리 원칙은 명확하다.

1. 세그먼트 사이 공백은 보간하지 않는다.
2. 윈도우는 한 세그먼트 안에서만 만든다.
3. 기본 입력은 **1초, 10샘플, 3채널 `(10, 3)` 시계열**로 고정한다.
4. 피처 모델의 기본 입력은 같은 1초 윈도우에서 계산한 **진폭 피처 18개**로 고정한다.
5. 2초 입력은 강건성 확인용으로만 사용하고, 3초 이상은 긴 세그먼트만 남는 선택 효과 때문에 주 비교에서 제외한다.
6. 길이가 10샘플보다 짧은 세그먼트는 보간·zero padding하지 않고 `판정 불가`로 보고한다.
7. 기존 세그먼트 전체 평균 제거는 기존 모델을 재현하는 **오프라인 benchmark 전처리**로 유지하되, 실시간 조기탐지 성능으로 해석하지 않는다.
8. 실시간 입력 검증 단계에서 과거와 현재 값만 사용하는 causal 전처리를 별도로 비교한다.

### 입력 계약 v1 한눈에 보기

| 구분 | 제안 |
|---|---|
| 샘플링 | 10 Hz |
| 채널 순서 | `AI0_Vibration`, `AI1_Vibration`, `AI2_Current` |
| 주 윈도우 | 1초 = 10샘플 |
| 이동 간격 | 0.5초 = 5샘플 |
| 시계열 입력 | `X_seq: float32[batch, 10, 3]` |
| 피처 입력 | `X_amp: float32[batch, 18]` |
| 윈도우 생성 | 세그먼트 내부에서만 생성 |
| 공백 처리 | 세그먼트 사이 보간 금지 |
| 짧은 세그먼트 | `assessable=False`, 모델 입력에서 제외하되 분모와 개수 보고 |
| 주 학습 방식 | 정상 데이터만 학습하는 이상탐지 |
| 분할 | 세그먼트 GroupKFold + 정상 시간순 block |
| 임계값 | 각 fold의 train 정상 점수 q99 |
| 금지 입력 | 절대 시각, 파일명·`src`, `seg_uid`, `label`, `Equipment_state`, fold·block, 사후 해석값 |
| 주 평가 | 세그먼트 FPR, 탐지율과 커버리지, time-block 안정성, 탐지 지연 |

## 1. 왜 입력 형태를 먼저 고정해야 하는가

현재 저장소에는 규칙 기반, 예측, 그래프, 분포, 복원 계열 모델 결과가 이미 있다. 하지만 입력 길이, 전처리, 피처 범위, 분할 단위가 달라지면 모델 점수를 직접 비교할 수 없다. 특히 이 데이터는 아래 이유로 임의의 입력 구성이 성능을 크게 부풀릴 수 있다.

- 정상은 2022-07-12, 이상은 2022-07-17 데이터라 날짜가 곧 라벨이다.
- 정상·이상 파일의 숫자 표현 방식이 달라 파일 형식만으로도 라벨을 구분할 수 있다.
- 같은 세그먼트에서 만든 겹치는 윈도우는 독립 표본이 아니다.
- 이상 21개 세그먼트가 모두 하나의 이상 이벤트에 속한다.
- 긴 윈도우를 사용하면 짧고 어려운 이상 세그먼트가 평가에서 빠진다.
- 세그먼트 전체 통계는 초반 윈도우를 평가할 때 미래 데이터를 제공한다.

따라서 본 문서에서 말하는 입력 고정은 단순히 배열 크기를 맞추는 일이 아니라, **누수 방지·평가 대상 고정·실시간 사용 가능성 구분을 포함하는 데이터 계약**이다.

## 2. 원시 데이터 구성

| 항목 | 정상 | 이상 |
|---|---:|---:|
| 행 수 | 20,000 | 600 |
| 세그먼트 수 | 599 | 21 |
| 날짜 | 2022-07-12 | 2022-07-17 |
| 세그먼트 내부 표본 간격 | 거의 모두 0.1초 | 0.1초 |
| 최대 세그먼트 길이 | 50샘플, 5초 | 50샘플, 5초 |
| 이벤트 수 | 정상 하루 | 이상 이벤트 1건 |

원본 주요 컬럼은 다음과 같다.

| 컬럼 | 의미 | 모델 입력 여부 |
|---|---|---|
| `TimeStamp` | 측정 시각 | 금지. 정렬·세그먼트·시간 블록 생성에만 사용 |
| `AI0_Vibration` | 상부 진동 채널 | 사용 |
| `AI1_Vibration` | 하부 진동 채널 | 사용 |
| `AI2_Current` | 전류 채널 | 사용 |
| `Equipment_state` | 파일에 부여된 정상/이상 라벨 | 정답으로만 사용, 입력 금지 |

`Equipment_state`는 고부하·저부하를 뜻하는 운전 상태 컬럼이 아니다. 저장소에서 별도로 만든 `state`가 정상 데이터의 운전 상태이며, 번호 규약은 `0=고부하`, `1=저부하`다.

센서의 정확한 부착 위치는 가이드북만으로 모터 몸체인지 펌프 몸체인지 확정할 수 없다. 따라서 모델의 탐지 대상은 **유압펌프 모터-펌프 구동부 이상**으로 표현하고, 특정 기계 부품의 결함 원인을 직접 분류하는 입력으로 해석하지 않는다.

## 3. 세그먼트 구조 분석

### 3.1 확인된 사실

- 정상과 이상 모두 동일하게 여러 세그먼트로 나뉜다.
- 세그먼트 내부 타임스탬프는 단조 증가한다.
- 세그먼트 내부 간격은 0.1초이고, 내부에서 0.15초를 넘는 간격은 확인되지 않았다.
- 한 세그먼트는 최대 50샘플, 즉 최대 5초다.
- 세그먼트 사이에는 수 초의 관측 공백이 있다.
- 현재 센서 열에는 NaN이 없다. 즉 공백은 NaN 행으로 남은 결측이 아니라 행 자체가 없는 구간이다.

### 3.2 시간 간격을 구분해서 해석해야 한다

| 지표 | 정상 | 이상 | 의미 |
|---|---:|---:|---|
| 현재 세그먼트 시작→다음 세그먼트 시작 중앙값 | 7.958초 | 8.1295초 | 수집 또는 공정 사이클 간격 후보 |
| 현재 세그먼트 마지막 샘플→다음 세그먼트 첫 샘플 중앙값 | 4.2225초 | 5.3525초 | 실제 관측값이 없는 빈 구간 |
| 실제 빈 구간 범위 | 약 1.545~16.643초 | 약 1.780~8.572초 | 세그먼트마다 길이가 다름 |

기존 문서 일부의 “burst gap 7.958초”는 엄밀히 말하면 실제 빈 구간이 아니라 **시작→시작 간격**이다. 탐지 지연에 7.958초를 일괄적으로 더하면 세그먼트 길이까지 중복해서 포함할 수 있다.

탐지 지연은 당분간 다음 두 값으로 분리한다.

- `delay_in_segment_s`: 세그먼트 시작 후 첫 경보까지의 알고리즘 지연
- `delay_wallclock_s`: 실제 이상 발생 시점을 확보했을 때만 계산하는 현장 지연

수집 정책과 이상 발생 시점을 모르는 현재는 `delay_in_segment_s`를 주 지표로 사용한다. `+7.958초` 값은 비교 가능한 현장 지연이 아니라 시나리오 참고치로만 남긴다.

### 3.3 세그먼트 원인에 대한 판정

| 가설 | 데이터 근거 | 현재 판정 |
|---|---|---|
| 설비 이상 때문에 측정이 끊김 | 정상 데이터에도 같은 세그먼트와 공백이 반복됨 | 가능성 낮음 |
| 센서 자체가 불규칙하게 고장남 | 세그먼트 내부 10 Hz가 안정적이고 정상·이상 모두 같은 구조 | 가능성 낮음 |
| 로거가 일정 주기로 burst 저장 | 최대 50샘플 제한, 시작 간격 약 8초 | 가능성 높음, 추정 |
| 프레스/유압 유닛 동작 사이클에 맞춰 수집 | 정상·이상 모두 유사한 주기 | 가능성 있음, 추정 |
| 공백에도 측정했지만 파일에서 누락 | 원본 수집 정책이 없어 판정 불가 | 미확정 |
| 공백 동안 애초에 측정을 중지 | 원본 수집 정책이 없어 판정 불가 | 미확정 |

따라서 현재 보고서 표현은 다음처럼 제한한다.

> 세그먼트 경계는 정상과 이상에서 공통으로 나타나는 구조이므로 설비 이상 자체보다 공정 사이클 또는 수집·저장 정책에 의한 burst 구조로 추정한다. 다만 공백 구간의 측정 여부는 수집 사양서가 없어 확정할 수 없다.

### 3.4 추가 확인이 필요한 질문

1. 데이터 로거가 한 번에 최대 50개 행만 저장하도록 설정되었는가?
2. 약 8초의 시작 간격은 프레스 1사이클과 일치하는가?
3. 공백 동안 센서 측정을 멈춘 것인가, 측정했지만 CSV에 저장하지 않은 것인가?
4. 세그먼트 시작 신호가 설비 PLC 또는 트리거 신호와 연결되어 있는가?
5. 이상 이벤트의 실제 시작 시각은 언제인가?

위 질문은 세그먼트 처리 원칙보다 **현장 지연과 원인 해석을 확정하기 위해 필요**하다.

## 4. 보간과 세그먼트 분할 제안

### 4.1 현재 데이터에 대한 결정

현재 세그먼트 내부에는 결측 센서값과 비정상적인 시간 간격이 없다. 따라서 지금 데이터에 적용할 시계열 보간은 없다.

세그먼트 사이 공백을 10 Hz 연속 신호라고 가정해 채우면 관측값보다 매우 많은 가상 샘플을 생성하게 된다. 공백 동안 설비가 같은 상태였다는 근거도 없으므로 선형·스플라인·전방 채움 중 어느 방법도 물리적으로 정당화할 수 없다.

**결정: 세그먼트 사이 공백은 보간하지 않고 서로 다른 관측 단위로 유지한다.**

### 4.2 향후 실시간 데이터 결측 정책

향후 스트리밍 데이터에서 실제 내부 결측이 발견되면 공백의 위치와 길이를 먼저 구분한다.

| 상황 | 처리 제안 |
|---|---|
| 세그먼트 경계의 긴 공백 | 새 세그먼트 시작, 보간 금지 |
| 세그먼트 내부 1샘플 누락 | 모델이 등간격 입력을 요구할 때만 제한적으로 보간하고 `missing_mask` 보존 |
| 세그먼트 내부 2샘플 이상 연속 누락 | 해당 위치에서 세그먼트를 분리하거나 `판정 불가` 처리 |
| 짧은 세그먼트 | 길이를 늘리기 위한 보간·zero padding 금지 |
| 시간 역행·중복 | 입력 거부 또는 별도 품질 오류로 기록 |

보간을 수행하더라도 값만 채우고 끝내지 않고 `is_imputed`, `missing_count`, `max_gap_s`를 메타데이터에 남겨야 한다. 해당 값은 모델 입력 후보가 아니라 입력 품질과 판정 가능 여부를 설명하는 값이다.

## 5. 윈도우 길이 결정

현재 구현은 1초·2초·3초 윈도우를 0.5초씩 이동하며 만든다. 윈도우가 길수록 한 세그먼트의 신호를 더 많이 볼 수 있지만, 짧은 세그먼트가 평가에서 빠진다.

| 윈도우 | 정상 윈도우 | 이상 윈도우 | 정상 판정 불가 | 이상 판정 불가 |
|---:|---:|---:|---:|---:|
| 1초 | 3,264 | 96 | 69/599, 11.52% | 4/21, 19.05% |
| 2초 | 2,254 | 63 | 147/599, 24.54% | 8/21, 38.10% |
| 3초 | 1,400 | 38 | 239/599, 39.90% | 11/21, 52.38% |

3초 윈도우에서는 이상 세그먼트 절반 이상이 제외된다. 5초 윈도우는 길이 50인 이상 세그먼트 5개만 참여해 높은 성능이 나와도 전체 이상을 대표하지 못한다.

### 최종 제안

- **주 입력:** 1초 윈도우
- **보조 검증:** 2초 윈도우
- **진단용:** 3초 윈도우
- **모델 선택에서 제외:** 5초 윈도우
- **공통 이동 간격:** 0.5초

모든 성능표에는 `n_seg_valid`, `n_seg_undetermined`, `undetermined_ratio`를 함께 표시한다.

## 6. 모델 입력 계약 제안

### 6.1 T1: 원신호 시계열 입력

```text
X_seq.shape = (batch, 10, 3)
dtype        = float32
sample_rate  = 10 Hz
window       = 1.0 s
step         = 0.5 s

channel 0 = AI0_Vibration
channel 1 = AI1_Vibration
channel 2 = AI2_Current
```

적용 모델 후보:

- PCA raw-window reconstruction
- CNN DeepAnT forecasting
- LSTM forecasting
- CNN+LSTM autoencoder
- MTAD-GAT·GDN 계열

예측 모델에서는 `X_seq` 다음 시점의 3채널 값이 목표가 되고, 복원 모델에서는 `X_seq` 자체가 목표가 된다. 모델마다 목표는 달라도 **입력 윈도우와 채널 순서는 동일하게 유지**한다.

### 6.2 T2: 윈도우 통계 피처 입력

같은 1초 윈도우에서 각 채널의 아래 6개 피처를 계산한다.

```text
rms, peak, p2p, kurt, crest, skew
```

3채널 × 6개이므로 입력은 18차원이다.

```text
X_amp.shape = (batch, 18)
dtype       = float32
```

적용 모델 후보:

- MCD
- One-Class SVM
- HBOS
- COPOD
- Isolation Forest
- Deep SVDD 비교군

1초 10샘플에서 첨도와 왜도는 분산이 클 수 있으므로, 18개를 기본 계약으로 유지하되 이후 피처 안정성 분석에서 RMS·peak·p2p만 사용한 축소 입력을 ablation으로 비교한다.

### 6.3 기본 입력에서 제외할 피처

| 피처 | 제외 이유 | 허용 범위 |
|---|---|---|
| `cur_fit_resid_rms`, `cur_fit_r2`, `cur_fit_f_dev` | 세그먼트 전체에서 1회 계산해 미래 정보 포함, 날짜 교란 가능 | 오프라인 ablation |
| `vib_corr01`, `cur_ac1` | 세그먼트 전체에서 계산해 모든 윈도우에 복사 | 오프라인 ablation |
| `vib_rms_ratio` | 윈도우 단위라 causal하지만 단일 피처 AUC가 높아 이벤트 특화 가능 | 별도 ablation |
| shape 9개 전체 | 6개가 amplitude kurt·skew와 중복 | 비중복 피처만 별도 검토 |
| 전류 DC·세그먼트 평균 | 파일·날짜 차이를 학습할 위험 | 진단·민감도 분석 |
| FFT 결함 주파수 | 10 Hz 샘플링, 나이퀴스트 5 Hz로 모터 고주파 정보 소실 | 사용 금지 |

전류에서 보이는 약 0.6 Hz는 실제 결함 주파수라기보다 60 Hz 성분이 10 Hz 샘플링에서 접혀 관측된 alias 후보다. 따라서 고주파 결함 진단을 의미하는 FFT 피처로 해석하지 않는다.

### 6.4 메타데이터 계약

모델 배열과 별도로 아래 메타데이터를 유지한다.

## 7. 전처리 버전 제안

### 7.1 형식 누수 차단

정상과 이상 파일에는 다음 형식 차이가 있었다.

- 진동 소수 자릿수: 정상 6자리, 이상 8자리
- 전류의 1.19209 격자 배수 비율: 정상 0.19%, 이상 99.67%
- 세그먼트 DC 오프셋만으로도 높은 분리 성능

형식 피처의 AUC는 원시 데이터에서 1.000이었지만 형식 통일과 평균 제거 후 약 0.57~0.60으로 낮아졌다. 따라서 기존 `src/preprocess.py`의 형식 통일 단계는 모든 모델에 공통 적용한다.

### 7.2 benchmark 전처리와 causal 전처리 분리

현재 표준 전처리는 각 세그먼트의 전체 평균을 구해 모든 샘플에서 뺀다.

```python
dc = out.groupby("seg_uid")[channel].transform("mean")
```

이 방식은 기존 실험을 공정하게 재현하고 파일별 DC 차이를 차단하는 데는 유효하다. 하지만 세그먼트 초반 1초를 판정할 때 세그먼트 후반 샘플까지 평균 계산에 사용하므로 실시간 조기탐지에는 미래 정보가 들어간다.

따라서 입력의 배열 구조는 하나로 고정하되 전처리 버전을 명시한다.

| 버전 | 목적 | DC 처리 | 성능 해석 |
|---|---|---|---|
| `benchmark_v1` | 기존 모델 재현·모델 이론 비교 | 세그먼트 전체 평균 제거 | 오프라인 비교 성능 |
| `causal_candidate_v1` | 실시간 입력 검증 | 현재·과거 샘플만 사용하는 평균/필터 | 실시간 후보 성능 |

`causal_candidate_v1`에서는 다음 후보를 같은 입력 형태로 비교한다.

1. 현재 1초 윈도우 평균 제거
2. 과거 구간의 running mean 제거
3. causal high-pass filter
4. 이전 정상 세그먼트에서 추정한 고정 baseline 제거

윈도우 내 z-score는 진폭 정보를 함께 제거하므로 DC 제거와 동일하지 않다. 기존 CNN+LSTM AE의 `all3_zwin` 결과에서 세그먼트 오경보가 증가했으므로, 단순히 모든 채널을 z-score하는 방식을 기본안으로 채택하지 않는다.

실시간 검증이 끝날 때까지 보고서에는 “실시간 탐지 성능” 대신 **오프라인 세그먼트 기반 조기탐지 실험**으로 표현한다.

## 8. 학습·검증 분할 계약

### 8.1 분할 단위

같은 세그먼트의 겹치는 윈도우는 서로 매우 유사하다. 윈도우를 무작위로 train/test에 나누면 같은 파형 조각이 양쪽에 들어가므로 성능이 과대평가된다.

**분할의 최소 단위는 `seg_uid`다.**

### 8.2 제안 분할 두 종류

| 분할 | 목적 | 사용 방식 |
|---|---|---|
| `group_kfold_seg` | 세그먼트 중복을 막은 반복 비교 | 동일 세그먼트의 모든 윈도우를 같은 fold에 배치 |
| `time_block` | 시간이 지난 정상 데이터에서의 오경보 안정성 | 과거 정상 block으로 학습, 다음 정상 block으로 평가 |

모델 선택에서는 `time_block` 결과를 우선하고 `group_kfold_seg`를 보조 지표로 사용한다. 날짜와 파일 출처는 입력으로 사용하지 않는다.

### 8.3 이상 데이터 사용 원칙

이상 세그먼트는 21개지만 독립된 이상 사건 21건이 아니라 **한 날짜의 이상 이벤트 1건을 여러 burst로 나눈 것**이다.

- 주 모델은 정상 데이터만으로 학습한다.
- 이상 데이터는 최종 탐지 성향을 확인하는 평가용으로 사용한다.
- 이상 점수를 보고 모델 구조·피처·임계값을 반복 선택한 경우 이를 독립 테스트 성능이라고 표현하지 않는다.
- 21개 세그먼트의 탐지율을 새로운 21개 고장에 대한 일반화 성능으로 해석하지 않는다.
- 합성 이상은 민감도 진단용으로 사용하되, 실제 고장 데이터의 대체물로 표현하지 않는다.

### 8.4 스케일링과 임계값

- scaler는 각 fold의 train 정상 데이터에만 적합한다.
- 검증·이상 데이터에 `fit`하지 않는다.
- 이상 점수 임계값은 각 fold의 train 정상 점수 q99로 고정한다.
- 고부하·저부하별 임계값은 후속 실험에서 train 정상 데이터만 사용해 적합한다.
- 이상 라벨을 이용해 임계값이나 앙상블 가중치를 선택하지 않는다.

## 13. 최종 제안 문구

보고서와 발표에서는 다음처럼 요약할 수 있다.

> 정상·이상 데이터 모두에서 최대 5초의 burst와 수 초의 공백이 반복되고, 각 burst 내부는 안정적인 10 Hz 간격을 유지한다. 이에 세그먼트 경계를 설비 이상 자체가 아닌 공정 사이클 또는 수집 구조로 판단하고, 경계 사이를 보간하지 않았다. 모델 입력은 세그먼트 내부의 1초 3채널 시계열 `(10, 3)`과 동일 윈도우의 진폭 피처 18개로 고정하였다. 동일 세그먼트의 겹치는 윈도우가 학습과 평가에 동시에 포함되지 않도록 세그먼트 단위 분할을 사용하고, 길이가 부족한 세그먼트는 인위적으로 채우지 않고 판정 불가율로 함께 보고하였다. 기존 세그먼트 전체 평균 제거는 오프라인 모델 비교용으로 구분하고, 실시간 적용 단계에서는 과거·현재 데이터만 사용하는 causal 전처리를 별도로 검증한다.
